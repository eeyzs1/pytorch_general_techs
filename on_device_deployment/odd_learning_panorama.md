## 0. ODD 是什么

**端侧部署**把大模型（及语音、视觉、扩散等）放到手机、平板、PC、车机、IoT、MCU 等设备上本地运行。

核心约束四件事：**体积、算力、带宽、电池**。ODD 不是单一算法，而是从模型压缩到系统交付的全栈工程。

本仓库技术可粗分为六层：

```
① 变小变省     压缩 / 高效架构
② 跑得更快     推理优化 / 编译运行时
③ 落到硬件     NPU·框架·格式·国产栈
④ 做成系统     端云·服务·功耗·语音·浏览器
⑤ 可持续运营   训练个性化·OTA·安全·MLOps
⑥ 场景扩展     Agent·检索·MCU·扩散·车载
```

建议学习顺序：①→②→③→⑨实战 → 再按目标选 ④⑤⑥。

## 1. 模型压缩（Ch.1 · `01_model_compression/`）

> 目的：在可接受精度损失下，显著降低存储与计算。

| 技术 | 一句话 | 要点 |
|------|--------|------|
| **1.1 量化** | 高精度数改成低比特整数/浮点 | PTQ / QAT；对称·非对称；逐通道·逐组；AWQ/GPTQ/SmoothQuant/HQQ；混合精度；FP8 |
| **1.2 剪枝** | 删掉不重要的参数或结构 | 非结构化 / 结构化（头·FFN·层）/ N:M 半结构化 |
| **1.3 知识蒸馏** | 大模型教小模型 | 白盒（logits/特征/注意力）与黑盒（指令数据） |
| **1.4 低秩分解** | 大矩阵拆成两个小矩阵 | SVD/Tucker；与 LoRA 思想相通 |
| **1.5 超低比特** | 2-bit / 1.58-bit | BitNet 三值；产业 2-bit；原生 QAT 趋势 |
| **1.6 torchao** | PyTorch 官方量化栈 | 对接 `torch.export` → ExecuTorch |

**练习入口**：`1.1`–`1.6` notebooks。

## 2. 高效推理（Ch.2 · `02_efficient_inference/`）

> 目的：不改（或少改）权重，把生成过程做快、做省内存。

| 技术 | 一句话 | 要点 |
|------|--------|------|
| **2.1 KV Cache** | 缓存历史 Key/Value 免重复算 | INT8/4 量化；PagedAttention；淘汰（H2O 等）；TurboQuant |
| **2.2 注意力优化** | 降低注意力算力/内存 | FlashAttention；MQA/GQA；稀疏注意力；**MLA** |
| **2.3 推理加速** | 少跑层、少跑步、一次验证多 token | 投机解码 / Medusa / Eagle；连续批处理；Early Exit；GBNF 结构化输出 |
| **2.4 Prefill/Decode 分治** | 两阶段画像不同，分开优化 | Prefill 偏算力；Decode 偏带宽；可双图导出 |
| **2.5 长上下文** | 超长对话/文档仍可控 | YaRN/RoPE 外推；滑窗+全局；摘要压缩；检索替代硬扩 KV |

**练习入口**：`2.1`–`2.3` notebooks；2.4/2.5 见主文档。

## 3. 高效模型架构（Ch.3 · `03_efficient_architecture/`）

> 目的：从结构设计上就适合端侧。

| 技术 | 一句话 | 要点 |
|------|--------|------|
| **3.1 轻量化架构** | 小参数打出强效果 | SLM；深而窄（MobileLLM）；嵌入共享；GQA/RMSNorm 等 |
| **3.2 线性注意力 / SSM** | 复杂度从 O(n²) 降下来 | Linear Attention；Mamba 等状态空间模型 |
| **3.3 MoE** | 总参数大、每次只激活一部分 | 路由 Top-K；端侧要解决专家常驻/按需加载 |
| **3.4 硬件感知 NAS** | 按延迟/内存自动搜子网 | Once-for-All、MCUNet；手机 LLM 多选现成 SLM，MCU/CV 更常用 NAS |

**练习入口**：`3.1`–`3.3` notebooks。

## 技术选型速查（自学导航树）

完整版与注释见主文档「技术选型决策树」。自学时可按症状跳转：

```
模型太大？ → Ch.1 压缩 / Ch.3 架构 / Ch.13 选型
推理太慢？ → Ch.2（Prefill/Decode 分治）/ Ch.4 / Ch.5
内存不够？ → KV 量化·流式加载·TurboQuant/MLA（Ch.2、4）
要个性化？ → Ch.8（QLoRA / 多适配器）
选框架？   → Ch.5（iOS/Android/国产/CPU/浏览器/MCU）
要 Agent？  → Ch.14 + 检索 Ch.20 + 语法约束 Ch.2.3
要语音？   → Ch.7.7 + MCU Ch.15 + 流式管线 Ch.21
要发版运营？→ 安全 Ch.17 + OTA Ch.19 + MLOps Ch.24
要上车？   → Ch.23
出问题了？ → Ch.9 排障 + Ch.12 指标
```

**常用组合拳**（详解见主文档总结）：

1. 量化 + KV 优化：权重和缓存一起瘦  
2. 量化 + 投机解码：草稿与验证都更快  
3. 剪枝 + 蒸馏：先砍结构再把精度捞回来  
4. 编译优化 + NPU 适配：图要吃得下硬件  
5. 端云协同 + 隐私：难题上云、隐私留端  
6. MoE / 多 LoRA + 按需加载：别把所有专家常驻内存  
7. 系统共享基座（Ch.18）+ 只 OTA 适配器（Ch.19）：运营成本最低的一种形态

## 一句话收束

ODD 的学习全景 = **让模型变小** + **让推理变快** + **让硬件吃饱** + **让系统可运营** + **让场景真正可用**。  
本文是地图；主文档与 notebook 是公路与实车；趣味科普是给非技术同伴的解说词。
