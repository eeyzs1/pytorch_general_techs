# 术语表

> 按主题分组，中英对照 + 一句话定义。遇到陌生缩写先查这里。

## 推理性能指标

| 术语 | 全称 | 含义 |
|---|---|---|
| **TTFT** | Time To First Token | 从发请求到收到第一个 token。用户感知的「快不快」 |
| **TPOT / ITL** | Time Per Output Token / Inter-Token Latency | 后续每个 token 的间隔。用户感知的「流不流畅」 |
| **Prefill** | — | 一次读完整个 prompt、建 KV 的阶段。compute-bound |
| **Decode** | — | 逐 token 生成的阶段。memory-bound |
| **Goodput** | — | 满足 SLO 的请求占比。比吞吐更能反映真实可用性 |
| **MFU** | Model FLOPs Utilization | 训练时实际算力 / 峰值算力。50% 已很不错 |

## 缓存

| 术语 | 含义 |
|---|---|
| **KV Cache** | 注意力层缓存的 Key/Value 张量，避免 decode 时重算历史 |
| **Prefix Caching** | 跨请求复用相同前缀的 KV。必须从第 0 个 token 起完全一致 |
| **Prompt Caching** | 厂商提供的产品化前缀缓存（OpenAI/Anthropic/Google/DeepSeek） |
| **RadixAttention** | SGLang 的前缀缓存实现，用基数树组织 KV block |
| **PagedAttention** | 像虚拟内存一样按 block 管理 KV，消除碎片、支持共享 |
| **Cache Hit Rate** | 命中的 token / 总 prompt token。按 token 加权，不是按请求数 |
| **Cache Silo** | 缓存孤岛：多副本各自建缓存，容量无法共享 |
| **Cache-Aware Routing** | 按前缀亲和把请求路由到持有该缓存的副本 |
| **KV Offload** | 把 KV 从显存挪到 CPU 内存 / SSD / 远端 |
| **Semantic Caching** | 按语义相似度复用答案，有误命中风险 |
| **Context Rot** | 上下文越长，模型对其中信息的准确召回反而下降 |

## 并行与架构

| 术语 | 含义 |
|---|---|
| **TP / PP / DP** | 张量并行 / 流水并行 / 数据并行 |
| **EP** | Expert Parallelism，MoE 的专家分散到不同卡 |
| **CP / SP** | Context / Sequence Parallelism，长上下文切分 |
| **PD 分离** | Prefill 与 Decode 跑在不同 GPU 池，KV 通过高速互联传输 |
| **MoE** | Mixture of Experts，稀疏激活；总参数量 ≠ 激活参数量 |
| **GQA** | Grouped-Query Attention，多个 Q head 共享一组 KV head，直接缩小 KV |
| **MLA** | Multi-head Latent Attention，DeepSeek 的低秩 KV 压缩方案 |
| **FlashAttention** | IO-aware 注意力核，避免 N×N 矩阵写回 HBM |

## 量化与压缩

| 术语 | 含义 |
|---|---|
| **PTQ / QAT** | 训练后量化 / 量化感知训练 |
| **GPTQ / AWQ** | 两种主流 INT4 权重量化算法 |
| **SmoothQuant** | 把激活的量化难度转移到权重上，实现 W8A8 |
| **FP8 / FP4** | Hopper/Blackwell 之后的低精度格式，训练和推理都在用 |
| **蒸馏** | 大模型教小模型，企业降本最常用手段之一 |

## 应用架构

| 术语 | 含义 |
|---|---|
| **RAG** | Retrieval-Augmented Generation，检索后生成 |
| **Hybrid Search** | 稀疏（BM25）+ 稠密（向量）混合检索，常用 RRF 融合 |
| **Rerank** | 用 cross-encoder 对召回结果精排 |
| **GraphRAG** | 用知识图谱组织实体关系，支持多跳推理 |
| **Agentic RAG** | 由模型自己决定何时检索、检索什么 |
| **Function Calling / Tool Use** | 模型输出结构化调用，宿主执行后回填结果 |
| **MCP** | Model Context Protocol，连接 Agent 与工具/数据的事实标准。2026-07 版改为无状态核心 + 版本化扩展 |
| **Constrained Decoding** | 用文法/JSON Schema 约束输出，保证格式合法（XGrammar、llguidance、Outlines） |
| **Compaction** | 上下文接近上限时摘要成高保真笔记后重启 |
| **Tool-Result Clearing** | 清掉旧的、可重取的工具结果，保留调用记录 |
| **Sub-agent** | 子 agent，在独立上下文里干活，只把结论带回主上下文 |

## 工程治理

| 术语 | 含义 |
|---|---|
| **LLM Gateway** | 统一多模型接入、鉴权、重试、计费的一层代理 |
| **Model Routing** | 按难度/成本/延迟把请求分给不同模型 |
| **Guardrails** | 输入输出过滤、注入检测、PII 脱敏等安全护栏 |
| **LLM-as-Judge** | 用强模型给输出打分，需人工校准防偏见 |
| **Trace** | 一次请求的完整调用链记录，OTel `gen_ai` 语义约定已成通用标准 |
| **Golden Set** | 从真实流量采样固化的回归测试集 |
| **SLO** | Service Level Objective，如「TTFT p95 < 800ms」 |
