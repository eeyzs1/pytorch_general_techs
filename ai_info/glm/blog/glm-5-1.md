## 核心观点

GLM-5.1 是智谱面向长程任务(long-horizon)的模型,核心指标是"一次任务独立持续工作 8 小时以上"——在 METR 标准下,它是唯一达到 8 小时级的开源模型。这把开源模型的能力锚点从"单轮解题"推进到"多天级工程交付"。

在权威基准上,GLM-5.1 以 SWE-Bench Pro 刷新全球最佳成绩(超过 GPT-5.4 与 Claude Opus 4.6),三项综合平均位列全球第三、国产第一、开源第一。模型以 MIT 协议开源;同期智谱对 API 提价约 10%,为年内第三次,形成"权重免费、服务涨价"的商业组合。

## 关键发现 / 关键技术

### 1. 长程任务能力

一次任务持续 8 小时,考验的是跨数千步的目标保持与上下文管理。

- 一次任务独立持续 8 小时以上
- METR 标准下唯一 8 小时级开源模型
- 定位从"回答问题"转向"承接完整工程交付"

### 2. 基准成绩

- SWE-Bench Pro 刷新全球最佳,超过 GPT-5.4 与 Opus 4.6
- 三项综合平均:全球第三、国产第一、开源第一
- 开源阵营首次在长程编程维度领先闭源旗舰

### 3. 场景一:从零构建 Linux 桌面

- 8 小时、1200+ 步连续执行
- 从零构建完整 Linux 桌面环境
- 验证跨千步级任务的目标不漂移能力

### 4. 场景二:向量库性能优化

"模型当性能工程师"的完整闭环:定位瓶颈、修改、压测、再迭代。

- 655 轮迭代自主优化向量数据库
- QPS 从 3108 提升至 21472,达 6.9 倍
- 优化对象是真实生产形态的数据库系统

### 5. 场景三:KernelBench GPU 内核优化

- L3 难度,24 小时以上持续迭代
- 几何平均加速 3.6 倍,对比 torch.compile 的 1.49 倍
- 模型产出的内核超越通用编译优化基线

### 6. 开源协议

- MIT 协议完全开源,商用无附加条件
- 权重、推理代码同步开放

### 7. 商业化信号

- 同期 API 提价约 10%,为年内第三次
- 权重免费与服务涨价并行:开源换生态、服务收费换算力
- 对重度用户,自托管开源权重成为对冲涨价的主要路径

### 8. 能力边界的含义

- 8 小时是 METR 标准下的量程锚点,不是任务时长上限
- 三大场景分别覆盖系统构建、性能优化、内核工程三类交付物
- 开发者可以把"能否 8 小时自驱"当作任务分派给模型的准入判断

## 实践意义

GLM-5.1 把"8 小时独立工作"变成可量化的开源能力下限,意味着个人开发者与中小企业首次能零成本获得接近前沿闭源的长程 Agent 能力。KernelBench 3.6×(超过 torch.compile 的 1.49×)说明这类模型已能胜任 GPU 内核级性能工程;655 轮迭代的向量库优化则展示了"模型当 SRE/性能工程师"的完整闭环。对团队而言,选型考量从"单点智力"转向"长时稳定性 + 成本结构"。

## 跨厂商对比

- 与 [Kimi K2.6](../../kimi/blog/kimi-k2-6.md) 对比:两者都押注长视野 Agent 能力,K2.6 代表 Moonshot 的旗舰路线,GLM-5.1 以 MIT 开源 + 8 小时 METR 指标把该能力下放给社区
