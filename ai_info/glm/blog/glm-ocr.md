# GLM-OCR:SOTA 复杂文档解析(GLM-OCR: SOTA Complex Document Parsing)

- **发布日期**: 2026-02-02
- **检索日期**: 2026-09-29

## 核心观点

GLM-OCR 是一个 0.9B 参数的专用文档解析模型(CogViT 400M 视觉编码 + GLM-0.5B 语言模型),在 OmniDocBench V1.5 上以 94.6 分登顶,整体能力接近 Gemini-3-Pro——用不到 1B 的模型逼近闭源旗舰的文档理解水平,是"小模型专用路线"对"大模型通用路线"的一次正面对撞。

模型覆盖手写体、复杂表格(直接输出 HTML)、印章、票据、多语言混排等传统 OCR 的硬骨头;训练上把 MTP(多 Token 预测)损失引入 OCR 任务。工程侧兼容 vLLM/SGLang/Ollama,PDF 解析速度 1.86 页/秒,定价 0.2 元/百万 tokens,约 1 元可处理 2000 张 A4(传统方案成本的 1/10),并提供开源 SDK。

## 关键发现 / 关键技术

### 1. 极小体量,旗舰级解析

0.9B 对打闭源旗舰,靠的是任务收窄与架构分工。

- 总参数 0.9B = CogViT 400M(视觉)+ GLM-0.5B(语言)
- OmniDocBench V1.5:94.6 分登顶
- 整体接近 Gemini-3-Pro
- 专用小模型在单一任务上具备与通用旗舰竞争的能力

### 2. 硬场景覆盖

- 手写体识别
- 复杂表格:直接输出 HTML 结构,保留合并单元格语义
- 印章、票据、多语言混排
- 覆盖政务/金融/档案数字化的高频痛点场景
- HTML 输出可直接进入下游解析与结构化入库流程

### 3. 训练技术

- MTP(多 Token 预测)损失引入 OCR 训练
- 视觉-语言联合优化,而非传统流水线式 OCR
- 结构化输出(HTML)内生于生成过程,无需后处理规则

### 4. 部署兼容性

三大主流推理框架全兼容,Ollama 路径打开了端侧想象。

- 推理框架兼容:vLLM / SGLang / Ollama
- Ollama 支持意味着可本地/端侧运行
- PDF 解析速度:1.86 页/秒

### 5. 成本结构

- 定价:0.2 元/百万 tokens
- 1 元约 2000 张 A4,为传统方案的 1/10
- 开源 SDK 支持私有化集成
- 解析成本下降直接改变 RAG 数据覆盖策略

### 6. 与通用多模态路线的分野

- 0.9B 专用模型 vs 千亿级通用旗舰:任务收窄换来成本与部署优势
- 文档解析是高频、重复、格式敏感的任务,天然适合专用模型
- OmniDocBench V1.5 94.6 分证明专用路线未牺牲精度
- 整体接近 Gemini-3-Pro,而参数量级相差悬殊

## 实践意义

GLM-OCR 把"复杂文档数字化"的成本压到传统方案的 1/10,且 0.9B 的体量意味着可在 Ollama 上做本地/端侧部署,满足金融票据、档案电子化、法务合同等隐私敏感场景。表格直接输出 HTML 的设计省去了版面分析后处理,对 RAG 管线是即插即用的前置组件。对正在建设企业知识库的团队,解析成本的量级下降意味着以前"太贵不值得解析"的长尾文档现在都能入库——知识库的覆盖率逻辑被改写。

## 跨厂商对比

- 与 [GLM-5.3-Flash](glm-5-3-flash.md) 对照:同属"小体量 + 免费开放"家族,5.3-Flash 面向通用推理,GLM-OCR 专攻文档解析,两者组合可低成本搭建多模态 Agent
- 与 [GLM-5V-Turbo:多模态 Coding 基座](glm-5v-turbo.md) 对比:5V-Turbo 把视觉融合进预训练基座走通用路线,GLM-OCR 用 0.9B 专用模型在单一任务逼近旗舰,多模态的两种工程取舍
- 与 [GLM-ASR-Nano:高鲁棒性语音识别](glm-asr-nano.md) 互补:OCR + ASR 构成"文档 + 语音"的输入侧双通道,均为小体量 SOTA 路线
