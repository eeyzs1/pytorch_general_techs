# Scaling Pain:超大规模 Coding Agent 推理实践(Scaling Pain: LLM Inference Practices for Hyperscale Coding Agents)

- **原文链接**: [Scaling Pain: LLM Inference Practices for Hyperscale Coding Agents](https://www.zhipuai.cn/zh/research/159)
- **作者**: 智谱推理基础设施团队
- **发布日期**: 2026-04-29
- **检索日期**: 2026-09-29
- **标签**: #推理基础设施 #PD分离 #SGLang #智谱 #CodingAgent #稳定性

## 核心观点

智谱推理基础设施团队复盘了日均数亿次 Coding 调用规模下的线上稳定性攻坚:2026 年 3 月起,高并发长上下文场景出现乱码、复读、生僻字等异常输出。团队发现本地复现必须模拟高峰期的 Prefill 请求堆积才能触发,实测异常率约万分之 3-5,这类"只在生产高峰显形"的缺陷是规模化推理独有的工程挑战。

文章给出两项可复用的方法论:一是把投机采样指标当作模型输出的"心电图"(accept_length 持续低于 1.4、accept_rate 高于 0.96 即为异常信号);二是定位出两个竞态缺陷——PD 分离异步 Abort 导致 KV Cache 复用竞态,以及 HiCache 的 read-before-ready 问题(已修复合入 SGLang PR #22811)。修复后异常率从万分之十几降至万分之三以下。

## 关键发现 / 关键技术

### 1. 问题画像:高峰期专属的输出异常

异常只在"高并发 × 长上下文"同时满足时出现,这决定了复现与定位的难度。

- 日均数亿次 Coding Agent 调用,3 月起高并发长上下文出现乱码、复读、生僻字
- 本地全量回放需模拟高峰 Prefill 堆积才能复现,实测异常率约万分之 3-5
- 传统"回放流量样本"的复现方法对时序敏感缺陷失效
- 单变量压测(只加并发或只加长度)均无法触发

### 2. 异常信号:投机采样指标当"心电图"

投机采样本来是加速手段,在这里反向充当了输出质量探针。

- accept_length 持续低于 1.4 → 草稿模型与目标模型分布偏离,输出即将劣化
- accept_rate 高于 0.96 属于异常高位 → 目标模型输出退化为高确定性复读
- 信号可在 serving 框架内零成本采集,早于用户可见的乱码报警
- 适用于任何部署投机采样的推理栈,具备跨厂商可迁移性
- 两个阈值(1.4 / 0.96)可直接作为生产告警规则落地

### 3. 竞态修复一:PD 分离异步 Abort

第一个根因藏在请求生命周期的清理路径里。

- 请求被 Abort 后 KV Cache 仍被复用,新旧请求状态互相污染
- 高峰期 Prefill 堆积放大了竞态窗口,异常率恶化到万分之十几
- 修复后异常率降至万分之三以下,回到基线水平

### 4. 竞态修复二:HiCache read-before-ready

第二个根因属于上游框架缺陷,修复直接回馈社区。

- 分层存储中读请求早于写入完成,读到半初始化缓存
- 修复已合入 SGLang 上游:PR #22811
- 同类部署 SGLang + 分层缓存的团队可直接受益

### 5. LayerSplit 分层存储收益

稳定性修复之外的正面优化:缓存分层与长上下文高度互补。

- 命中率达 90% 时,40k-120k 长上下文吞吐提升 10%-132%
- 上下文越长,收益越显著,与 Coding Agent 的长会话特征匹配
- 分层存储 + 竞态修复构成本次攻坚的"防"与"治"两面

### 6. 方法论沉淀

- 复现生产缺陷要还原"峰值时序",而非只还原流量内容
- 把推理框架的内部指标(如投机采样)纳入可观测性体系
- 上游开源协作(SGLang PR)是规模化推理团队的必要能力
- 稳定性指标与异常率基线(万分之三)应成为推理服务的常规 SLO

## 实践意义

这篇文章是"推理稳定性工程"的实战范本:当 Coding Agent 把调用量推到日均数亿次,输出质量不再是纯粹的模型问题,而是模型 × 调度 × 缓存 × 网络的联合系统问题。对自研 serving 栈的团队,投机采样指标异常检测与竞态修复路径可直接借鉴;对选型者,它解释了为什么同一模型在不同推理栈上的稳定性可能天差地别——竞态缺陷属于框架而非模型,换模型救不了坏基础设施。
