# ZCode 代码上传争议:致歉、开源与第三方审计(ZCode Data Upload Incident: Apology, Open Source & Audit)

- **原文链接**: [智谱ZCode代码上传事件收尾公告(搜狐)](http://news.sohu.com/a/1078841832_114760) / [TechWeb 报道](https://m.techweb.com.cn/marticle/2026-09-28/2979401.shtml)
- **作者**: 智谱官方公告(搜狐号)/ TechWeb
- **发布日期**: 2026-09-28
- **检索日期**: 2026-09-29
- **标签**: #ZCode #数据隐私 #默认开启 #开源 #第三方审计 #危机响应

## 核心观点

9 月 18 日,开发者 ferstar 发现 ZCode 在本地写入 313MB 加密包(解压后 345MB、42411 个文件,其中 .git 占 86.6%),质疑其在未经充分提示的情况下上传代码工作区与 Git 历史;海外报道称该客户端曾发起 564 次上传尝试。智谱当日致歉,定位问题源头为默认开启的"代码库索引"中 Repo Wiki 云端生成功能触发上传,并称 Wiki 生成后即销毁。

此后十天,事件以"移除功能→开源→第三方审计→补偿"四步收尾:9 月 19 日 v3.14.0 移除 Repo Wiki 与上传链路;9 月 21 日 ZCode 以 Apache-2.0 开源并邀请信通院、绿盟双审计(确认云端零数据留存/已删除);9 月 28 日发布收尾公告,给出"你不发起,不上云"承诺。事件期间(9/21–23)股价累计下跌逾 16%。

## 关键发现 / 关键技术

### 1. 事件起点(09-18):313MB 加密包
- 开发者 ferstar 发现 ZCode 本地写入 313MB 加密包:解压后 345MB、共 42411 个文件,其中 .git 目录占 86.6%
- 质疑点:未经充分提示即上传代码工作区与完整 Git 历史
- 海外报道:该客户端曾发起 564 次上传尝试
- 争议放大因素:加密包内容不可直读,用户无法自行审计上传范围,只能依赖厂商单方面披露

### 2. 致歉与根因定位(09-18)
- 智谱当日致歉,定位问题源头:默认开启的"代码库索引"中,Repo Wiki 云端生成功能触发上传
- 官方解释:Wiki 生成后即销毁,云端不留存代码内容

### 3. 处置时间线(09-19 → 09-28)
- 09-19:发布 v3.14.0,移除 Repo Wiki 功能与上传链路
- 09-21:ZCode 以 Apache-2.0 协议开源(github.com/zai-org/ZCode);邀请中国信通院 + 绿盟科技双审计,确认云端零数据留存、历史数据已删除
- 09-28:发布收尾公告——承诺"你不发起,不上云";产品更新至 v3.14.3
- 补偿:付费用户赠送额度重置卡;9/28–10/7 向全员发放 10 万份 × 1 亿 token

### 4. 市场影响
- 9/21–23 股价累计下跌逾 16%,收尾公告后修复情况待后续观察

### 5. 响应模式复盘
- 四步响应(移除功能→开源→第三方审计→补偿)在十天里完成,节奏快于多数同类数据争议事件
- 开源 + 信通院/绿盟双审计是关键增量:把"厂商自证"升级为"第三方可验证",直接回应"Wiki 生成后即销毁"无法被用户独立验证的信任缺口
- 补偿规模(10 万份 × 1 亿 token)与付费用户额度重置卡把善后转化为留存手段,也侧面说明事件对付费基本盘的冲击不小

## 实践意义

ZCode 事件的核心教训是"默认开启的云端功能"等于隐性数据外发:一个索引功能叠加云端 Wiki 生成,就能把 4 万余个文件(含完整 Git 历史)送上云。工程上的对应解法与沙箱化思路一致——把"上传什么"从一揽子许可改为按动作、按路径的显式边界。危机响应侧,智谱的"移除功能→开源→第三方审计→补偿"四步在十天里完成,把信任事件部分转化为透明度资产;但逾 16% 的股价回撤说明市场对"默认开启"类隐私问题的定价远高于修复速度。对使用编码 Agent 的团队,这是把"客户端会传什么"纳入供应商尽职调查清单的直接理由。

## 跨厂商对比

- 与 [Beyond Permission Prompts](../../anthropic/engineering/beyond-permission-prompts.md) 对比:Anthropic 用文件系统/网络双重沙箱替代频繁权限提示,让"能碰什么"在架构层收窄;ZCode 事件的根因恰是相反路径——默认开启 + 云端生成把边界扩张到了用户未明确授权的数据,事后才回撤
- 与 [OpenAI 对 TanStack npm 供应链攻击的回应](../../openai/research/our-response-to-the-tanstack-npm-supply-chain-attack.md) 对照:两起都是开发者信任事件,TanStack 是外部攻击者窃取凭证、响应以预防性轮换证书为主;ZCode 是产品自身设计缺陷、响应以开源 + 双第三方审计自证,路径不同但都指向"信任需独立验证"
- 与 [GLM Flash ZCode Night Free](glm-flash-zcode-night-free.md) 对比:免费夜间的 ZCode 用量策略把开发者引入生态,本次事件则显示编码 Agent 的隐私设计缺陷会以股价与信任的双重成本清算——增长红利与信任风险同源
- 与 [Claude Code 最佳实践](../../anthropic/engineering/claude-code-best-practices.md) 对比:最佳实践强调把数据访问边界显式化、让用户可预期每次操作的影响面;ZCode 事件是反面教材——默认开启的云端功能让用户在不知情下让渡了数据主权
