# 分数不是模型（The Score Is Not the Model）

- **原文链接**: [The Score Is Not the Model](https://huggingface.co/blog/Omartificial-Intelligence-Space/the-score-is-not-the-model)
- **作者**: Omer Nacar（Community 版）
- **发布日期**: 2026-09-09
- **检索日期**: 2026-09-29
- **标签**: #评测方法学 #误差预算 #阿拉伯语 #基准测试 #LLM评测

## 核心观点

基准分数测的是"模型 + 外围系统"：API 可用性、提示模板、重试策略、内容审核、题目渲染管线都会写进最终数字，而榜单很少交代这些。作者在 HUMAIN M3 上用三套阿拉伯语基准、9497 道题建立逐项误差预算：病毒学子集首跑仅 14%——76/100 条是 403 HTML 错误页被计成"答错"，重试后回到 59.6%；MMMLU 首跑 78.14%→重试 83.14%（+5.00）；提示模板缺陷修复 +3.76；内容审核三种口径相差 1.64；自适应推理开启 +20.84（协议变更，非缺陷修复）。

由此提出六条评测规范：展示实际结果计数；服务失败与答错分离；校验渲染后题目；报告执行设置；说明分数测的到底是什么；交错对比保留记录。

## 关键发现 / 关键技术

### 1. 误差预算逐项记账

- MMMLU 重试修复 +5.00（78.14%→83.14%）；提示模板缺陷修复 +3.76——两项"非模型"修正合计近 9 分，超过多数代际差。
- 内容审核三种口径相差 1.64：被拦截算不算答错、分母含不含被拦截题，口径不同分数不同，分数与分母必须一起报。
- 自适应推理 +20.84：这是协议变更带来的真实能力差异，但记账上必须与缺陷修复分开。

### 2. 403 错误页案例：基础设施伪装成模型失败

- 病毒学子集首跑 14%：76/100 条是 403 HTML 错误页被当作答案判错——服务端故障伪装成模型无能。
- 重试后回升到 59.6%，一条重试策略就"提升"了 45 分以上。
- 教训：不分离服务失败与答错的评测，测的是 API 稳定性而非模型。
- 403 页面本可通过简单校验（返回内容是否为合法题目）自动拦截，成本远低于其造成的结论污染。

### 3. 六条评测规范

- 展示实际结果计数：分数背后有多少条真实作答，缺失多少。
- 服务失败与答错分离：403、超时、审核拦截不得混入错误率。
- 校验渲染后题目：模板变量未替换、语言混排都会污染题目本身。
- 报告执行设置、说明分数测什么、交错对比并保留完整记录以便复查。

### 4. 阿拉伯语评测的现实

- 三套阿拉伯语基准、9497 题的规模，足以让每一项系统性误差显著显形。
- 阿拉伯语的模板渲染、混合方向文本等问题，使"校验渲染后题目"在此类场景尤为关键。

## 实践意义

对任何跑分团队：先建误差预算表，再读分数——一次重试、一次模板修复就能移动 3-5 分，超过多数模型代差。"分数 + 分母 + 执行设置"三件套应成为报告默认格式；交错对比（新旧配置交替执行）能排除时间漂移。对阿拉伯语等低资源场景，外围系统噪声更大，规范执行的价值更高。
