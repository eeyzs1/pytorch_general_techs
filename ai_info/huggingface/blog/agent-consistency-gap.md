# Agent 通过了任务，还能再次通过吗？（Consistency: Can an Agent That Passes Once Pass Again?）

- **原文链接**: [altk-evolve-consistency](https://huggingface.co/blog/ibm-research/altk-evolve-consistency)
- **作者**: IBM Research
- **发布日期**: 2026-09-15
- **检索日期**: 2026-09-29
- **标签**: #Agent评测 #一致性 #自进化 #AppWorld #可靠性

## 核心观点

IBM Research 提出"一致性鸿沟"（consistency gap）指标：同一任务多次执行的完全成功率与单次平均通过率之间的落差——此前几乎无人报告。实测 ReAct agent（GPT-4.1）在 AppWorld 上单次平均通过率 77%，但同任务连跑 5 次全部成功仅 53%，24 分的落差意味着平均分严重高估了可依赖性。

解法是自进化框架：Consistency Analyzer 定位跨执行易翻转的不稳定步骤并诊断其决策边界（尖锐 vs 平坦）；Guideline Generator 把诊断转化为针对性指南写入情景记忆，后续执行注入。结果：5/5 全成功率 +16 点、相似任务泛化 +13 点、单次准确率不降。论文 arXiv:2609.08832。核心主张：agent 评测应报告多次执行方差，而非只报平均。

## 关键发现 / 关键技术

### 1. 一致性鸿沟的量化

- ReAct + GPT-4.1 在 AppWorld：单次平均通过率 77%，连跑 5 次全成功率仅 53%，落差 24 点。
- 通过率接近 50% 的任务最容易翻转：处于决策平坦区，成败近似抛硬币。
- 该指标此前几乎无人报告——排行榜上的平均分掩盖了可靠性问题。
- 一致性鸿沟在部署侧的含义：用户遇到的是"单次执行"，而非平均分布。

### 2. 诊断：尖锐 vs 平坦决策边界

- Consistency Analyzer 对比多次执行轨迹，定位跨执行易翻转的步骤。
- 诊断决策边界形状：尖锐边界处模型稳定正确/错误；平坦边界处微小扰动即翻转结果，是可靠性损失主源。
- 诊断输出不是"哪个任务失败"，而是"哪类分支在什么条件下不稳定"。

### 3. 指南生成与情景记忆注入

- Guideline Generator 把诊断结果转成针对性指南（何时该确认、哪类分支易错），写入情景记忆。
- 后续执行注入指南——不改动模型权重，只改运行时上下文，成本远低于微调。
- 闭环类似"给 agent 自动写运营手册"，手册内容由失败模式分析自动生成。

### 4. 效果与边界

- 5/5 全成功率 +16 点；相似（未专门训练的）任务泛化 +13 点；单次准确率无损失。
- 收益来自减少翻转而非提高上限：顶部任务仍取决于模型能力，框架负责把"有时能过"变成"总能过"。
- 指南注入与具体骨干模型解耦，换用更强底座时框架仍可复用。

## 实践意义

对要上生产的 agent 团队，单次平均通过率不能作为上线依据：应报告 N 次执行的全成功率与方差。情景记忆注入指南的做法成本极低（无训练），可作为任何 ReAct 类 agent 的可靠性补丁。"决策边界平坦"也为解释失败提供了新词汇：问题不在知识缺口，而在选项间差异过小、模型被环境噪声左右。
