# Kimi 企业合作伙伴计划:FDE 模式(Kimi Enterprise Partner Program)

## 核心观点

Kimi 发布企业合作伙伴计划,与 IT 服务商/系统集成商共建"前线部署工程师"(FDE)队伍:伙伴接入 Kimi 模型与 Kimi Hosted Agents 做定制开发,交付成果沉淀为可复用的行业方案,一线行业认知回流研发形成闭环。

首批 5 家伙伴覆盖金融云、政企、私有化运维等场景:华胜天成、金山云、亚康股份、亚信科技、中软国际。这可视为对 OpenAI"部署公司"模式的中国式回答——不自建数千人交付团队,而是激活存量集成商渠道换取覆盖速度。

## 关键发现 / 关键技术

### 1. FDE 模式

- 前线部署工程师(FDE)深入客户现场,负责定制开发与落地
- 接入对象:Kimi 模型 + Kimi Hosted Agents,支持定制开发

### 2. 成果沉淀机制

- 每个项目的交付成果沉淀为可复用行业方案
- 一线行业认知回流研发,反哺模型与产品迭代,形成闭环
- 分工边界清晰:Kimi 出模型与 Agent 平台,伙伴出行业知识与交付人力

### 3. 双产品接入

- Kimi 模型:API/私有化接入,适配已有系统
- Kimi Hosted Agents:托管智能体底座,伙伴在其上做行业定制开发,无需自建 Agent 基建

### 4. 首批 5 家伙伴

| 伙伴 | 关键数据 |
|------|----------|
| 华胜天成 | 16000+ 客户、37 个交付中心 |
| 金山云 | 服务近半数国有大行 |
| 亚康股份 | 1000+ 客户、7×24 私有化支持 |
| 亚信科技 | 200+ 政企大模型项目 |
| 中软国际 | 约 7 万员工 |

### 5. 生态卡位

- 5 家伙伴分别在金融云、政企软件、算力运维等细分领域拥有存量客户与交付能力
- 伙伴渠道可快速覆盖 Kimi 自营难以触达的国企/政企市场
- 私有化支持能力(如亚康股份 7×24)补齐 Kimi 在本地化运维上的短板

## 实践意义

- **FDE 是 AI 落地的稀缺角色**:既懂模型又懂客户业务的工程师决定项目成败,借伙伴渠道比自建团队扩张更快
- **方案复用降低边际成本**:一次交付、多客户复用,是行业方案商业化的关键杠杆
- **对国内厂商有借鉴意义**:模型厂商 × 集成商的分工模式,贴合国内企业软件的采购与交付习惯

## 跨厂商对比

- 与 [OpenAI 成立部署公司](../../openai/research/openai-launches-the-deployment-company.md) 对比:OpenAI 自建交付组织啃最难的企业改造,Kimi 以伙伴 FDE 模式换渠道规模,成本更轻但深度依赖伙伴能力
- 与 [Building an AI-Native Engineering Team](../../openai/research/building-an-ai-native-engineering-team.md) 对比:OpenAI 讲企业内部团队的 AI 原生化,Kimi 讲外部交付生态的组织创新
