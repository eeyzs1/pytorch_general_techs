## 核心观点

Legora 是面向法律与专业服务的 agentic 操作系统，服务超过 10 万名专业人士、1,800 多个企业法务部门与律所，覆盖 50 多个市场。其最枯燥的工作流之一是财务报表 tie-out（核对）：把草案报表中的每个数字与试算平衡表、合并日程表及上年报表逐一比对，直到每一项都吻合——法务工程师 Percevale Perks 称这项工作"可能耗掉一整晚，有时是几天"。

使用 GPT-6 Astra 后，Legora 的 Agent 在单次运行中数分钟完成了跨 41 份文档的 tie-out：核对每个余额与辅助日程、浮出金额断点、逐项记录检查过程，最终给法律专业人士留下一份可逐行复核的细粒度记录。Agent 负责穷举式比对，专家保留对每项结果的判断权——这种人在回路的设计正是 Legora 向审计、税务、合规与风险领域扩展的基础。

## 关键发现 / 关键技术

### 1. 复杂财务上下文的规模化处理
- 41 份文档在单次 Agent 运行中完成核对，全程数分钟；每一项检查都被记录，形成清晰的审查轨迹。
- 关键变化是处理能力：能摄取大量文档、消化复杂信息并提取所有不同科目与数字（Perks 语）。

### 2. 准确性、完整性与可靠性（BAR 基准）
- 在 Legora 的 Agentic 推理基准（BAR，基于真实用例的端到端法律任务）上，GPT-6 Astra 在该财务报表工作流中较上一代模型提升近 40%；全部 BAR 任务平均提升约 3%。
- Astra 找到了 Legora 预先植入的全部 4 处错误，包括隐藏在收入附注中的一笔 50 万英镑差额。
- 它保留了上一代模型做对的每一项检查，并多完成了约 50 项——更快、更完整的第一轮核对，最终决定权仍在法律专家。
- 厂商信息：欧洲/英国初创，技术行业，通过 API 使用。

## 实践意义

这个案例展示了长文档、强结构化核对类工作流的 agent 化路径：不追求替代专业判断，而是把"穷举比对 + 全程留痕"交给模型，把判断与签字留给人。对审计、税务、合规等同样以逐项核对为核心的行业，"植入错误全中 + 检查覆盖率提升"是比泛用基准更有说服力的验收标准。

同时它也提示了评估的现实：单点工作流近 40% 的提升与全任务平均 3% 的提升并存，选对场景（大批量结构化核对）比平均能力更能兑现新模型价值。
