## 三、模糊匹配算法详解

### 3.1 算法选型决策树

```
待匹配文本长度？
├─ 短文本（< 20字符，如地区名）
│   └─ 用课时27 的 rapidfuzz（编辑距离变体）
├─ 中等文本（20-100字符，如商品名）
│   ├─ 需要精确去重？
│   │   └─ SimHash（近似相等检测，O(1) 查找）
│   └─ 需要相似度排序？
│       └─ MinHash + LSH（集合相似度，支持 Top-K 查询）
└─ 长文本（> 100字符，如地址、商品描述）
    └─ 词向量（Word2Vec/BERT）+ 余弦相似度
```

### 3.2 SimHash：近似文本去重

**原理**：把任意长度文本压缩成 64 位指纹，**相似文本的指纹只有少数几位不同**（汉明距离小）。

**适用**：海量文本的精确去重（如新闻去重、商品名去重）。

```python
"""
simhash_dedup.py
SimHash 文本去重
依赖：pip install simhash
"""
from simhash import Simhash, SimhashIndex
import pandas as pd

# ========== 1. 计算每条文本的 SimHash ==========
products = [
    {"id": "P1", "name": "Apple iPhone 15 Pro Max 256GB 深空黑色"},
    {"id": "P2", "name": "苹果 iPhone15ProMax 256G 深空灰"},
    {"id": "P3", "name": "iPhone 15 Pro Max 256G 黑色"},
    {"id": "P4", "name": "华为 Mate 60 Pro 512G 雅丹黑"},
    {"id": "P5", "name": "HUAWEI Mate60 Pro 512GB 黑色"},
]

# Simhash 计算文本指纹（默认 64 位）
for p in products:
    p["simhash"] = Simhash(p["name"])

# ========== 2. 建立索引，支持快速近邻查询 ==========
# SimhashIndex 用哈希分桶加速，避免两两比较
objs = [(p["id"], p["simhash"]) for p in products]
# key 参数控制分桶数，影响查询速度和召回
index = SimhashIndex(objs, k=3)  # k=汉明距离阈值，<=3 视为相似

# ========== 3. 查询相似文本 ==========
query = Simhash("苹果 iPhone15 Pro Max 256G 深空黑")
dups = index.get_near_dups(query)
print(f"相似商品: {dups}")
# 预期返回 P1/P2/P3

# ========== 4. 批量去重 ==========
# 对每条记录查找已存在的相似记录，合并为同一组
groups = {}
group_id = 0
for p in products:
    found = index.get_near_dups(p["simhash"])
    if found:
        # 找到已有组，归入
        existing_group = next((groups[f] for f in found if f in groups), None)
        if existing_group is not None:
            groups[p["id"]] = existing_group
            continue
    # 新建组
    groups[p["id"]] = f"GROUP_{group_id}"
    group_id += 1

for p in products:
    p["sku_group"] = groups[p["id"]]
    print(f"{p['id']} [{p['sku_group']}] {p['name']}")
```

**关键参数**：
- `k`（汉明距离阈值）：越小越严格。商品名建议 3-5，新闻建议 3。
- 指纹位数：默认 64 位，支持百万级数据。亿级建议 128 位。

### 3.3 MinHash + LSH：集合相似度

**原理**：把文本拆成词集合（或 n-gram 集合），用 MinHash 估算 Jaccard 相似度，用 LSH（Locality Sensitive Hashing）加速近邻查询。

**适用**：需要基于"词集合重叠度"判断相似度，且支持 Top-K 查询的场景。

```python
"""
minhash_dedup.py
MinHash + LSH 文本相似度
依赖：pip install datasketch
"""
from datasketch import MinHash, MinHashLSH
import jieba  # 中文分词

def text_to_minhash(text, num_perm=128):
    """把文本转成 MinHash（需要先分词）"""
    mh = MinHash(num_perm=num_perm)
    # 中文用 jieba 分词，英文用 split
    words = set(jieba.cut(text))
    for w in words:
        mh.update(w.encode("utf-8"))
    return mh

# ========== 1. 准备数据 ==========
products = [
    {"id": "P1", "name": "Apple iPhone 15 Pro Max 256GB 深空黑色"},
    {"id": "P2", "name": "苹果 iPhone15ProMax 256G 深空灰"},
    {"id": "P3", "name": "华为 Mate 60 Pro 512G 雅丹黑"},
    {"id": "P4", "name": "HUAWEI Mate60 Pro 512GB 黑色"},
]

for p in products:
    p["minhash"] = text_to_minhash(p["name"], num_perm=128)

# ========== 2. 建立 LSH 索引 ==========
# threshold: Jaccard 相似度阈值，>= 此值视为候选相似对
# num_perm: MinHash 置换函数数，越多越精确，128 是平衡值
lsh = MinHashLSH(threshold=0.5, num_perm=128)
for p in products:
    lsh.insert(p["id"], p["minhash"])

# ========== 3. 查询相似项 ==========
for p in products:
    result = lsh.query(p["minhash"])
    # 排除自己
    similar = [r for r in result if r != p["id"]]
    if similar:
        # 计算精确 Jaccard 相似度
        for s_id in similar:
            s = next(x for x in products if x["id"] == s_id)
            jaccard = p["minhash"].jaccard(s["minhash"])
            print(f"{p['id']} ~ {s_id} (Jaccard={jaccard:.2f}): {p['name']} ~ {s['name']}")
```

### 3.4 SimHash vs MinHash 对比

| 维度 | SimHash | MinHash + LSH |
|------|---------|---------------|
| 相似度度量 | 汉明距离 | Jaccard 相似度 |
| 适合文本类型 | 整体相似（编辑距离小） | 词集合重叠（词序无关） |
| 查询复杂度 | O(1) 桶查找 | O(1) LSH 桶查找 |
| 精度 | 中等 | 较高（可调 num_perm） |
| 典型场景 | 网页去重、新闻去重 | 商品名去重、文档相似 |
| 中文支持 | 需先分词 | 需先分词 |

### 3.5 词向量相似度（进阶）

**适用**：语义相似但字面差异大的场景（如"手机"和"mobile phone"）。

```python
"""
词向量相似度
依赖：pip install sentence-transformers
用预训练模型把文本转成向量，计算余弦相似度
"""
from sentence_transformers import SentenceTransformer
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# 加载多语言模型（支持中英文）
model = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')

texts = [
    "Apple iPhone 15 Pro Max 256GB",
    "苹果15 Pro Max 256G 手机",
    "华为 Mate 60 Pro",
    "HUAWEI mate60 pro 手机",
]

# 编码成向量
embeddings = model.encode(texts)

# 计算两两余弦相似度
sim_matrix = cosine_similarity(embeddings)
for i in range(len(texts)):
    for j in range(i + 1, len(texts)):
        print(f"{sim_matrix[i][j]:.2f}  {texts[i]}  ~  {texts[j]}")
```

> **工程提示**：词向量方法精度最高但计算成本大（GPU 加速下百毫秒/条）。生产环境建议先用 SimHash/MinHash 粗筛，再用词向量精排。

## 四、大规模文本去重工程实现（Spark）

```python
"""
大规模商品名去重：Spark + SimHash
适合：亿级商品名
"""
from pyspark.sql import SparkSession, functions as F, types as T
import hashlib

spark = SparkSession.builder.appName("ProductDedup").getOrCreate()

# ========== 1. UDF：计算 SimHash ==========
def compute_simhash(text, hash_bits=64):
    """简化版 SimHash，生产环境用 simhash 库"""
    if not text:
        return None
    # 分词
    import jieba
    tokens = list(jieba.cut(text))
    # 每个词 hash 后加权累加
    v = [0] * hash_bits
    for token in tokens:
        h = int(hashlib.md5(token.encode()).hexdigest(), 16)
        for i in range(hash_bits):
            if h & (1 << i):
                v[i] += 1
            else:
                v[i] -= 1
    # 生成指纹
    fingerprint = 0
    for i in range(hash_bits):
        if v[i] > 0:
            fingerprint |= (1 << i)
    return fingerprint

simhash_udf = F.udf(compute_simhash, T.LongType())

# ========== 2. 计算所有商品名的 SimHash ==========
df = spark.read.parquet("/warehouse/ods/products")
df = df.withColumn("simhash", simhash_udf(F.col("product_name")))

# ========== 3. 分桶 + 桶内比较 ==========
# SimHash 特性：相似文本的指纹只有少数几位不同
# 把 64 位指纹分成 4 段（每段 16 位），相似文本至少有一段完全相同
df = df.withColumn("bucket_1", F.col("simhash") & 0xFFFF)
df = df.withColumn("bucket_2", (F.col("simhash") >> 16) & 0xFFFF)
df = df.withColumn("bucket_3", (F.col("simhash") >> 32) & 0xFFFF)
df = df.withColumn("bucket_4", (F.col("simhash") >> 48) & 0xFFFF)

# 对每个桶，桶内两两比较汉明距离（桶内数据量小）
# 用 self-join + 汉明距离过滤
# popcount(simhash_a XOR simhash_b) <= 3
# Spark 没有内置 popcount，用 bit_count（Spark 3.3+）或 UDF

@F.udf(T.IntegerType())
def hamming_distance(a, b):
    return bin(a ^ b).count("1")

# 桶1内匹配
matches_1 = df.alias("a").join(
    df.alias("b"),
    (F.col("a.bucket_1") == F.col("b.bucket_1")) &
    (F.col("a.product_id") < F.col("b.product_id")) &
    (hamming_distance(F.col("a.simhash"), F.col("b.simhash")) <= 3)
).select(
    F.col("a.product_id").alias("id_a"),
    F.col("b.product_id").alias("id_b"),
    F.col("a.product_name").alias("name_a"),
    F.col("b.product_name").alias("name_b")
)
# 对 bucket_2/3/4 重复，最后 union 去重

matches_1.show(truncate=False)
```

## 五、企业主数据管理（MDM）

### 5.1 什么是主数据

**主数据（Master Data）**：企业内跨业务系统共享的核心实体数据，如：
- 客户主数据（Customer）
- 商品主数据（Product）
- 供应商主数据（Supplier）
- 组织/员工主数据（Organization）
- 地址主数据（Location）

**特点**：变化频率低、被多个系统引用、对业务一致性影响大。

**与交易数据的区别**：
```
交易数据（Transactional）：订单、支付、点击——每秒产生，只增不改
主数据（Master）：客户、商品——每天变化少，但一旦错误影响所有交易分析
```

### 5.2 为什么需要 MDM

**没有 MDM 的痛苦**：
```
CRM 系统：客户 "张三"，手机 13800138000
ERP 系统：客户 "张 三"，手机 +8613800138000
财务系统：客户 "Zhang San"，手机 13800138000

→ 三个系统认为是三个客户
→ 营收统计重复计算
→ 信用额度无法统一管控
→ 营销活动重复触达
```

**MDM 的目标**：为每个核心实体建立**唯一、准确、权威**的 Golden Record（黄金记录），分发给所有下游系统。

### 5.3 MDM 体系架构

### 5.4 Golden Record 构建流程

**Golden Record**：每个实体的"最佳版本"，从多源数据中冲突解决后得到。

```
Golden Record 构建流程：

Step 1: 实体识别（本课时第三节）
  └─ 用 SimHash/MinHash 判断"张三"/"Zhang San"/"张 三"是否同一实体

Step 2: 实体对齐（课时27 第三节）
  └─ 用 ID Mapping 联通分量算法合并

Step 3: 冲突解决
  └─ 同一字段多源不一致时，怎么选？
     ├─ 规则法：指定优先源（如 CRM 的客户名 > ERP 的客户名）
     ├─ 时间法：取最新值
     ├─ 可信度法：按数据源可信度加权
     └─ 人工裁决：关键字段（如信用额度）人工审核

Step 4: 补全
  └─ A 源有手机号无邮箱，B 源有邮箱无手机号 → 合并取并集

Step 5: 质量校验（课时23）
  └─ Golden Record 必须通过质量规则才能发布

Step 6: 发布与分发
  └─ 版本化发布，推送到下游系统
```

```python
"""
golden_record_builder.py
Golden Record 构建示例
"""
import pandas as pd
from datetime import datetime

# 多源客户数据（已经过实体对齐，同一 customer_group 是同一人）
data = [
    # group, source, name, phone, email, address, updated_at, source_trust
    {"gid": "G1", "source": "CRM",  "name": "张三",  "phone": "13800138000", "email": None,          "address": "北京市朝阳区", "updated": "2024-01-15", "trust": 0.9},
    {"gid": "G1", "source": "ERP",  "name": "张 三", "phone": None,           "email": "z@x.com",     "address": None,           "updated": "2024-03-01", "trust": 0.7},
    {"gid": "G1", "source": "APP",  "name": "Zhang San", "phone": "+8613800138000", "email": "z@x.com", "address": "北京朝阳", "updated": "2024-06-01", "trust": 0.8},
    {"gid": "G2", "source": "CRM",  "name": "李四",  "phone": "13900139000", "email": "l@y.com",      "address": "上海市浦东新区", "updated": "2024-02-01", "trust": 0.9},
]

df = pd.DataFrame(data)

def build_golden_record(group_df):
    """对一个实体组构建 Golden Record"""
    golden = {"gid": group_df["gid"].iloc[0]}

    # 字段级冲突解决策略
    field_strategy = {
        "name":   "trust",      # 按源可信度选
        "phone":  "normalize",  # 标准化后取最新
        "email":  "merge",      # 合并去重
        "address": "trust",     # 按源可信度选
    }

    for field, strategy in field_strategy.items():
        non_null = group_df[group_df[field].notna()].copy()
        if non_null.empty:
            golden[field] = None
            continue

        if strategy == "trust":
            # 取可信度最高的源
            best = non_null.loc[non_null["trust"].idxmax()]
            golden[field] = best[field]
        elif strategy == "normalize":
            # 标准化后取最新
            non_null["normalized"] = non_null[field].str.replace(r"[^\d]", "", regex=True)
            latest = non_null.loc[non_null["updated"].idxmax()]
            golden[field] = latest["normalized"]
        elif strategy == "merge":
            # 合并所有非空值，去重
            values = non_null[field].unique().tolist()
            golden[field] = values[0] if len(values) == 1 else "|".join(values)

    golden["sources"] = ",".join(group_df["source"].unique())
    golden["record_count"] = len(group_df)
    golden["golden_updated"] = datetime.now().strftime("%Y-%m-%d")
    return golden

# 按 gid 分组构建
golden_records = df.groupby("gid").apply(build_golden_record).reset_index(drop=True)
print(golden_records.to_string())
```

### 5.5 MDM 模式选型（架构师视角）

| 模式 | 特点 | 适用场景 | 代表工具 |
|------|------|---------|---------|
| **注册表模式（Registry）** | MDM 只存索引和映射，不存完整数据 | 只需识别同一实体，不改源系统 | 自研 + 图算法 |
| **合并模式（Coexistence）** | MDM 存 Golden Record，双向同步源系统 | 需要统一视图，也需回写源系统 | Informatica MDM |
| **集中模式（Transaction）** | MDM 是唯一权威，源系统只读 | 强管控场景（金融、合规） | SAP MDG |

**选型建议**：
- 初创/中小公司：注册表模式（成本低，自研可行）
- 成长期公司：合并模式（兼顾统一与灵活）
- 强监管行业：集中模式（合规优先）

### 5.6 MDM 实施路线图

```
阶段1（1-2月）：试点

阶段2（3-6月）：扩展

阶段3（6-12月）：深化
  └─ 双向同步（合并模式）

  └─ 组织建设（数据治理员角色）
```

### 练习3：MDM 方案设计

假设一家连锁零售企业，有 POS 系统、电商系统、会员系统三个数据源，客户数据严重不一致。设计一个 MDM 实施方案，包括：
- 选哪种 MDM 模式？为什么？
- Golden Record 的冲突解决策略
- 分阶段实施路线

---

## 七、小结

| 问题 | 推荐算法 | 工具 |
|------|---------|------|
| 海量文本精确去重 | SimHash | simhash 库 / Spark UDF |
| 词集合相似度去重 | MinHash + LSH | datasketch |
| 语义相似（中英文混合） | 词向量 + 余弦相似度 | sentence-transformers |
| 超大规模去重 | Spark + SimHash 分桶 | Spark UDF |
| 企业级实体治理 | MDM 体系 | 自研 / Informatica / SAP MDG |

**核心工程原则**：
1. **分层过滤**：SimHash 粗筛 → MinHash/词向量精排，避免全量两两比较
2. **Golden Record 不是一次性的**：需要持续维护，处理新增源和冲突
3. **MDM 是组织问题不是纯技术问题**：没有治理流程和责任人，技术方案落不了地
4. **从注册表模式起步**：不要一上来就做集中模式，试点成功再扩展
