## 二、转换问题分类

多源数据进来后，按"结构化程度"可分三类，每类的转换难点完全不同：

| 数据类型 | 典型来源 | 结构特征 | 转换难点 | 主力工具 |
|---------|---------|---------|---------|---------|
| 非结构化（纯文本） | 聊天记录、客服对话、日志、工单正文 | 无固定字段分隔，自由文本 | 字段边界靠语义/正则识别；消息类型多样（文本/图片/链接/引用） | 正则、规则引擎、NLP |
| 半结构化（JSON/XML/CSV） | API 返回、配置文件、导出表单 | 有结构但 Schema 不固定，嵌套深 | 多层嵌套展开、数组 explode、Schema 漂移、编码与转义 | Spark `from_json`、pandas `json_normalize`、lxml |
| 富文本（HTML/邮件） | 网页抓取、邮件工单、富文本编辑器提交 | 有标签结构但混杂展示逻辑 | 去标签保留语义结构、正文与导航/广告分离、附件分离 | BeautifulSoup、`email` 库 |

**核心矛盾**：源端 Schema 灵活多变，目标端要稳定可分析。本课时的本质是"**在灵活性与可分析性之间找到折中点**"——既不能强求所有源统一格式，也不能放任混乱。

## 三、半结构化数据解析

### 3.1 JSON 解析（嵌套 JSON、数组展开）

#### 3.1.1 场景：API 返回的嵌套 JSON

第三方反馈平台 API 返回的数据往往是多层嵌套 + 数组：

```json
{
  "code": 0,
  "data": {
    "feedback_id": "FB20240115001",
    "user": {
      "user_id": "U10023",
      "phone": "13800138000",
      "region": "北京市"
    },
    "tags": ["支付问题", "退款"],
    "messages": [
      {"seq": 1, "type": "text", "content": "支付失败", "time": "2024-01-15 10:23:45"},
      {"seq": 2, "type": "image", "content": "https://cdn.xxx.com/1.png", "time": "2024-01-15 10:24:00"}
    ],
    "submit_time": "2024-01-15 10:25:00"
  }
}
```

目标：把 `messages` 数组展开成多行，每行一条消息记录。

#### 3.1.2 Spark 解析多层嵌套 JSON

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, from_json, get_json_object, explode, expr
from pyspark.sql.types import StructType, StructField, StringType, ArrayType, LongType

spark = SparkSession.builder.appName("JsonParse").getOrCreate()

# 原始数据：每行一个完整 JSON 字符串
df_raw = spark.read.text("hdfs:///data/feedback_api/2024-01-15/")

# 方法一：get_json_object 逐字段提取（适合字段少、层级浅）
df_flat = df_raw.select(
    get_json_object(col("value"), "$.data.feedback_id").alias("feedback_id"),
    get_json_object(col("value"), "$.data.user.user_id").alias("user_id"),
    get_json_object(col("value"), "$.data.user.phone").alias("phone"),
    get_json_object(col("value"), "$.data.user.region").alias("region"),
    get_json_object(col("value"), "$.data.submit_time").alias("submit_time"),
)

# 方法二：from_json + StructType（适合字段多、需复用 Schema）
# 先定义嵌套 Schema
msg_type = StructType([
    StructField("seq", LongType()),
    StructField("type", StringType()),
    StructField("content", StringType()),
    StructField("time", StringType()),
])

data_type = StructType([
    StructField("feedback_id", StringType()),
    StructField("user", StructType([
        StructField("user_id", StringType()),
        StructField("phone", StringType()),
        StructField("region", StringType()),
    ])),
    StructField("tags", ArrayType(StringType())),
    StructField("messages", ArrayType(msg_type)),
    StructField("submit_time", StringType()),
])

root_type = StructType([
    StructField("code", LongType()),
    StructField("data", data_type),
])

# 把字符串列解析成结构体
df_parsed = df_raw.select(from_json(col("value"), root_type).alias("root"))

# 展平非数组字段
df_base = df_parsed.select(
    col("root.data.feedback_id").alias("feedback_id"),
    col("root.data.user.user_id").alias("user_id"),
    col("root.data.user.phone").alias("phone"),
    col("root.data.user.region").alias("region"),
    col("root.data.submit_time").alias("submit_time"),
)

# 用 explode 把 messages 数组展开成多行
df_msg = df_base.withColumn("msg", explode(col("root.data.messages"))) \
    .select(
        "feedback_id", "user_id", "phone", "region", "submit_time",
        col("msg.seq").alias("msg_seq"),
        col("msg.type").alias("msg_type"),
        col("msg.content").alias("msg_content"),
        col("msg.time").alias("msg_time"),
    )

df_msg.show(truncate=False)
```

**关键函数对比**：

| 函数 | 输入 | 输出 | 适用场景 |
|------|------|------|---------|
| `get_json_object(col, path)` | 字符串 + JSONPath | 单个字符串值 | 字段少、层级浅、临时取数 |
| `from_json(col, schema)` | 字符串 + StructType | 结构体（可继续用 `.` 访问） | 字段多、需复用 Schema、要 explode 数组 |
| `explode(col)` | 数组列 | 多行（每行一个元素） | 把一对多数组展开成明细行 |
| `posexplode(col)` | 数组列 | 多行 + 位置索引 | 需要保留元素在数组中的位置 |

#### 3.1.3 pandas json_normalize

小数据量或单机处理时，pandas 的 `json_normalize` 更简洁：

```python
import pandas as pd
import json

with open("feedback.json", "r", encoding="utf-8") as f:
    raw = json.load(f)

# record_path 指定要展开的数组，meta 指定要带上的上层字段
df = pd.json_normalize(
    raw["data"],
    record_path="messages",
    meta=[
        "feedback_id",
        "submit_time",
        ["user", "user_id"],
        ["user", "phone"],
        ["user", "region"],
    ],
    record_prefix="msg_",   # 数组字段加前缀，避免与上层重名
)

print(df.columns.tolist())
# ['msg_seq', 'msg_type', 'msg_content', 'msg_time', 'feedback_id', 'submit_time', 'user.user_id', 'user.phone', 'user.region']
```

### 3.2 XML 解析

XML 在配置类、报表类数据中仍常见（如银行回单、SAP 导出）。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<orders>
    <order id="ORD20240115001">
        <customer>
            <name>张三</name>
            <phone>13800138000</phone>
        </customer>
        <items>
            <item sku="SKU001" name="商品A" qty="2" price="99.50"/>
            <item sku="SKU002" name="商品B" qty="1" price="199.00"/>
        </items>
        <total>298.00</total>
        <status>已支付</status>
    </order>
</orders>
```

```python
from lxml import etree
import pandas as pd

# 用 lxml 解析（性能优于标准库 ElementTree，且支持 XPath）
tree = etree.parse("orders.xml")
root = tree.getroot()

records = []
# XPath 定位每个 order 节点
for order in root.xpath("//order"):
    order_id = order.get("id")
    name = order.findtext("customer/name")
    phone = order.findtext("customer/phone")
    total = order.findtext("total")
    status = order.findtext("status")

    # 每个 item 展开成一行（一对多）
    for item in order.xpath("items/item"):
        records.append({
            "order_id": order_id,
            "customer_name": name,
            "customer_phone": phone,
            "sku_id": item.get("sku"),
            "sku_name": item.get("name"),
            "qty": int(item.get("qty")),
            "price": float(item.get("price")),
            "total_amount": float(total),
            "order_status": status,
        })

df = pd.DataFrame(records)
print(df)
```

**ElementTree vs lxml**：

| 维度 | xml.etree.ElementTree（标准库） | lxml（第三方） |
|------|-------------------------------|---------------|
| 安装 | 无需安装 | `pip install lxml` |
| XPath 支持 | 基础（不支持全部轴） | 完整 XPath 1.0 |
| 性能 | 一般 | 更快（C 实现） |
| 大文件 | `iterparse` 流式解析 | 同样支持 `iterparse` |
| 适用 | 简单 XML、无依赖环境 | 复杂 XPath、生产环境 |

### 3.3 CSV/TSV 处理

CSV 看似简单，工程中坑最多：编码、分隔符、引号转义、脏行。

```python
import pandas as pd

# 坑1：编码问题。导出文件可能是 GBK/GB18030/UTF-8-SIG（带 BOM）
# 用 chardet 自动探测（小文件），或按优先级试错
def read_csv_safe(path, sep=","):
    for encoding in ["utf-8-sig", "utf-8", "gbk", "gb18030"]:
        try:
            return pd.read_csv(path, sep=sep, encoding=encoding, dtype=str)
        except UnicodeDecodeError:
            continue
    raise ValueError(f"无法解码文件: {path}")

df = read_csv_safe("feedback.csv")

# 坑2：分隔符问题。TSV 用 \t，有的导出用 | 或 ;
# pandas 会自动推断，但显式指定更稳
df_tsv = pd.read_csv("data.tsv", sep="\t", encoding="utf-8")

# 坑3：引号转义。字段内含分隔符或换行，需正确处理 quotechar
# engine="python" 容错性更好但慢，engine="c"（默认）快但严格
df = pd.read_csv(
    "messy.csv",
    sep=",",
    quotechar='"',          # 字段引用符
    escapechar="\\",        # 转义符
    dtype=str,              # 先全按字符串读，避免类型推断错误
    keep_default_na=False,  # 不要把 "NA"/"null" 自动转成 NaN
    na_values=["", "NULL"], # 显式指定哪些值算空值
)

# 坑4：脏行。行数与表头列数不一致
# on_bad_lines="skip" 跳过（pandas>=1.3），或用 csv 模块逐行处理
df = pd.read_csv("dirty.csv", on_bad_lines="skip", dtype=str)
```

**CSV 处理原则**：
1. **先按字符串读**（`dtype=str`），避免 pandas 把"001"转成 1、把"2024-01-01"转成 Timestamp 后又丢精度
2. **显式指定编码和分隔符**，不要依赖自动推断（生产环境会出事）
3. **脏行单独记录**，不要静默丢弃，否则数据对不上账

## 四、非结构化文本字段化

### 4.1 正则表达式提取（复习 L0 课时5，深化）

正则是非结构化文本字段化的第一工具。这里不再讲基础语法，重点讲**命名捕获组**和**复杂日志解析**两个工程化技巧。

#### 4.1.1 命名捕获组

```python
import re

# 普通捕获组：靠位置取值，字段一多就乱
pattern_pos = r"(\d{4}-\d{2}-\d{2}) (\d{2}:\d{2}:\d{2}) (\S+) (.*)"
m = re.match(pattern_pos, "2024-01-15 10:23:45 ERROR something wrong")
date, time, level, msg = m.groups()   # 难维护

# 命名捕获组：(?P<名称>模式)，可读性强、不怕顺序变动
pattern_named = r"(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) (?P<level>\S+) (?P<msg>.*)"
m = re.match(pattern_named, "2024-01-15 10:23:45 ERROR something wrong")
print(m.groupdict())
# {'date': '2024-01-15', 'time': '10:23:45', 'level': 'ERROR', 'msg': 'something wrong'}

# 用 groupdict() 直接转 DataFrame 行，工程化最方便
```

#### 4.1.2 复杂日志解析

```python
import re
import pandas as pd

# Nginx 访问日志示例：
# 192.168.1.1 - - [15/Jan/2024:10:23:45 +0800] "GET /api/order HTTP/1.1" 200 1234 "https://ref.com" "Mozilla/5.0"
nginx_pattern = re.compile(
    r'(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] '
    r'"(?P<method>\S+) (?P<path>\S+) (?P<proto>[^"]+)" '
    r'(?P<status>\d+) (?P<size>\S+) '
    r'"(?P<referer>[^"]*)" "(?P<ua>[^"]*)"'
)

records = []
with open("access.log", "r", encoding="utf-8", errors="replace") as f:
    for lineno, line in enumerate(f, 1):
        m = nginx_pattern.match(line)
        if m:
            records.append(m.groupdict())
        else:
            # 未匹配的行单独记录，便于排查
            records.append({"_raw": line.strip(), "_lineno": lineno, "_parse_error": True})

df = pd.DataFrame(records)

# 解析失败率监控（生产环境关键指标）
fail_rate = df["_parse_error"].mean() if "_parse_error" in df.columns else 0
print(f"解析失败率: {fail_rate:.2%}")
```

**工程化要点**：正则解析必须留"兜底通道"——未匹配的行不能丢，要带原始内容和行号落表，方便后续修正正则。生产环境应监控解析失败率，超过阈值（如 1%）告警。

### 4.2 聊天记录字段化（核心痛点）

聊天记录是用户反馈分析最常见但也最难处理的源。难点在于：消息类型多样（文本/图片/链接/引用/文件/红包）、格式因平台而异、消息内容跨多行。

#### 4.2.1 各平台聊天导出格式

```
微信导出 txt（典型格式）:
2024-01-15 10:23:45 张三
你好，我想咨询退款

2024-01-15 10:24:12 李四(客服)
好的，请提供订单号

2024-01-15 10:25:30 张三
[图片]

2024-01-15 10:26:00 张三
订单号是 ORD20240115001


企业微信导出 txt（带部门）:
2024-01-15 10:23:45 张三(销售部)
你好，我想咨询退款

2024-01-15 10:24:12 李四(客服组)
[文件] 退款申请表.xlsx


钉钉导出 txt（时间与昵称分行）:
2024-01-15 10:23:45
张三: 你好，我想咨询退款

2024-01-15 10:24:12
李四: [链接]https://help.example.com/faq
```

**共同结构**：时间戳行 → 发送人 → 消息内容（可跨行）→ 空行分隔下一条。

#### 4.2.2 通用解析器设计

```python
import re
import pandas as pd
from dataclasses import dataclass, field
from typing import Optional

# ========== 1. 定义消息类型枚举 ==========
MSG_TYPES = {"文本", "图片", "文件", "链接", "语音", "视频", "引用", "红包", "系统消息", "未知"}

# ========== 2. 发送人正则：兼容微信/企业微信/钉钉三种格式 ==========
# 企业微信: "张三(销售部)"；微信: "张三"；钉钉单独一行 "张三: 内容"
SENDER_PATTERN = re.compile(
    r"^(?P<sender>[^(（\n]+?)"
    r"(?:[(（](?P<dept>[^)）]+)[)）])?$"
)

# ========== 3. 消息类型识别规则（按优先级） ==========
def detect_msg_type(content: str) -> str:
    """根据内容前缀识别消息类型"""
    content = content.strip()
    if not content:
        return "未知"
    # 系统消息（撤回、入群等）
    if content.startswith("撤回了一条消息") or content.startswith("加入了群聊"):
        return "系统消息"
    # 各种方括号标记
    type_map = [
        ("[图片]", "图片"), ("[image]", "图片"),
        ("[文件]", "文件"), ("[file]", "文件"),
        ("[语音]", "语音"), ("[视频]", "视频"),
        ("[红包]", "红包"), ("[转账]", "红包"),
        ("[链接]", "链接"), ("[引用]", "引用"),
    ]
    for marker, mtype in type_map:
        if content.startswith(marker):
            return mtype
    # URL 链接（无标记但有 http）
    if re.match(r"https?://", content):
        return "链接"
    return "文本"

def extract_content(content: str, msg_type: str) -> str:
    """剥离类型标记，返回纯内容"""
    if msg_type == "链接" and content.startswith("[链接]"):
        return content.replace("[链接]", "").strip()
    if msg_type == "引用" and content.startswith("[引用]"):
        return content.replace("[引用]", "").strip()
    for marker in ["[图片]", "[image]", "[文件]", "[file]", "[语音]", "[视频]", "[红包]", "[转账]"]:
        if content.startswith(marker):
            return content.replace(marker, "").strip()
    return content.strip()

# ========== 4. 主解析函数 ==========
# 时间行正则：2024-01-15 10:23:45（兼容秒可选、日期分隔符 - 或 /）
TIME_LINE = re.compile(
    r"^(?P<date>\d{4}[-/]\d{1,2}[-/]\d{1,2})\s+"
    r"(?P<time>\d{1,2}:\d{2}(?::\d{2})?)\s*"
    r"(?P<rest>.*)$"
)

def parse_chat_export(text: str, platform: str = "auto") -> pd.DataFrame:
    """
    解析聊天导出 txt，返回结构化 DataFrame。

    platform: wechat / wework / dingtalk / auto（自动判断）
    返回列: msg_time, sender, dept, msg_type, content, raw
    """
    lines = text.split("\n")
    records = []
    i = 0
    n = len(lines)

    # 用于累积跨行消息内容
    current = None  # 当前正在累积的消息 dict

    while i < n:
        line = lines[i].rstrip("\r")
        m = TIME_LINE.match(line.strip())

        if m:
            # 遇到新的时间行，先把上一条累积的消息存起来
            if current is not None:
                _finalize(current, records)
            date_str = m.group("date").replace("/", "-")
            time_str = m.group("time")
            # 补齐秒位：10:23 → 10:23:00
            if time_str.count(":") == 1:
                time_str += ":00"
            rest = m.group("rest").strip()

            # 钉钉格式：时间单独一行，下一行才是 "发送人: 内容"
            if platform == "dingtalk" or (platform == "auto" and not rest):
                i += 1
                if i < n:
                    rest = lines[i].rstrip("\r").strip()
                else:
                    rest = ""

            # 解析发送人：可能是 "张三" / "张三(销售部)" / "张三: 内容"
            sender = ""
            dept = ""
            inline_content = ""
            if ": " in rest:
                # 钉钉 "张三: 你好"
                sender_part, inline_content = rest.split(": ", 1)
                sm = SENDER_PATTERN.match(sender_part.strip())
                if sm:
                    sender = sm.group("sender").strip()
                    dept = sm.group("dept") or ""
            else:
                # 微信/企业微信：发送人单独，内容在后续行
                sm = SENDER_PATTERN.match(rest)
                if sm:
                    sender = sm.group("sender").strip()
                    dept = sm.group("dept") or ""

            current = {
                "msg_time": f"{date_str} {time_str}",
                "sender": sender,
                "dept": dept,
                "content_lines": [inline_content] if inline_content else [],
                "raw": [line],
            }
        else:
            # 非时间行：累积到当前消息内容
            if current is not None:
                if line.strip() == "":
                    # 空行：如果当前消息已有内容，则结束本条
                    if current["content_lines"]:
                        _finalize(current, records)
                        current = None
                    # 否则跳过连续空行
                else:
                    current["content_lines"].append(line.strip())
                    current["raw"].append(line)
            # current 为 None 时的非空行视为文件头部垃圾，忽略
        i += 1

    # 文件结束时把最后一条存起来
    if current is not None:
        _finalize(current, records)

    return pd.DataFrame(records)

def _finalize(current: dict, records: list):
    """把累积的消息 dict 转成记录并加入列表"""
    content = "\n".join(current["content_lines"]).strip()
    msg_type = detect_msg_type(content)
    clean_content = extract_content(content, msg_type)
    records.append({
        "msg_time": current["msg_time"],
        "sender": current["sender"],
        "dept": current["dept"],
        "msg_type": msg_type,
        "content": clean_content,
        "raw": "\n".join(current["raw"]),
    })
```

**聊天记录解析的工程原则**：
1. **保留原始内容**（`raw` 列）：正则永远会有漏网之鱼，留 raw 方便回溯和修正规则
2. **消息类型单独成列**：图片/链接/文本要分开统计，不能混在一列

4. **解析失败率监控**：每批解析都算一下失败率，平台格式变更会突然拉高失败率

### 4.3 邮件字段化

邮件工单是另一类常见源。`.eml` 是标准邮件格式，用 Python 标准库 `email` 解析。

```python
import email
from email import policy
from email.header import decode_header
import pandas as pd
import os

def decode_str(s) -> str:
    """解码邮件头（主题/发件人/收件人可能带编码）"""
    if s is None:
        return ""
    parts = decode_header(s)
    result = []
    for content, charset in parts:
        if isinstance(content, bytes):
            result.append(content.decode(charset or "utf-8", errors="replace"))
        else:
            result.append(content)
    return "".join(result)

def get_body(msg) -> str:
    """提取邮件正文，优先纯文本，其次 HTML"""
    if msg.is_multipart():
        # 多部分：遍历找 text/plain 或 text/html
        text_part, html_part = None, None
        for part in msg.walk():
            ctype = part.get_content_type()
            cdisp = str(part.get("Content-Disposition", ""))
            if "attachment" in cdisp:
                continue   # 附件单独处理
            if ctype == "text/plain" and text_part is None:
                text_part = part
            elif ctype == "text/html" and html_part is None:
                html_part = part
        part = text_part or html_part
        if part is None:
            return ""
    else:
        part = msg

    payload = part.get_payload(decode=True)
    charset = part.get_content_charset() or "utf-8"
    body = payload.decode(charset, errors="replace")
    # 如果是 HTML，简单去标签（复杂场景交给 4.5 节 BeautifulSoup）
    if part.get_content_type() == "text/html":
        import re
        body = re.sub(r"<[^>]+>", "", body)
    return body.strip()

def parse_eml(path: str) -> dict:
    """解析单个 .eml 文件，返回结构化字段 + 附件列表"""
    with open(path, "rb") as f:
        msg = email.message_from_binary_file(f, policy=policy.default)

    record = {
        "ticket_file": os.path.basename(path),
        "from": decode_str(msg.get("From")),
        "to": decode_str(msg.get("To")),
        "cc": decode_str(msg.get("Cc")),
        "subject": decode_str(msg.get("Subject")),
        "date": msg.get("Date"),
        "body": get_body(msg),
        "attachments": [],
    }

    # 收集附件
    for part in msg.walk():
        cdisp = str(part.get("Content-Disposition", ""))
        if "attachment" in cdisp:
            filename = decode_str(part.get_filename())
            record["attachments"].append({
                "filename": filename,
                "size": len(part.get_payload(decode=True) or b""),
                "content_type": part.get_content_type(),
            })

    record["attachment_count"] = len(record["attachments"])
    return record

# 批量解析一个目录下的所有 .eml
eml_dir = "tickets/"
records = [parse_eml(os.path.join(eml_dir, f))
           for f in os.listdir(eml_dir) if f.endswith(".eml")]
df = pd.DataFrame(records)
print(df[["ticket_file", "from", "subject", "date", "attachment_count"]])
```

### 4.4 表单提交记录解析（动态 Schema）

自定义表单（问卷星/金数据/自建表单）的字段不固定——运营随时可能加一个"满意度"或"建议"字段，导致 Schema 漂移。

```json
// 表单提交记录（同一张表单，不同时期字段不同）
[
  {"submit_id": "F001", "form_id": "Q2024", "fields": {"name": "张三", "phone": "13800138000", "feedback": "好"}},
  {"submit_id": "F002", "form_id": "Q2024", "fields": {"name": "李四", "phone": "13900139000", "feedback": "一般", "satisfaction": 4}},
  {"submit_id": "F003", "form_id": "Q2024", "fields": {"name": "王五", "phone": "13700137000", "feedback": "差", "satisfaction": 2, "channel": "APP"}}
]
```

**处理策略**：动态字段不要试图横向扩展成列（Schema 一直在变，表结构会爆炸），而是落到 `Map<String,String>` 列 + 常用字段单独提取。

```python
import pandas as pd
import json

records = json.load(open("form_submissions.json", encoding="utf-8"))

# 策略一：常用字段提取成列，其余放 extra_fields（Map）
# 适合：80% 字段稳定，20% 字段偶尔变化
def flatten_form(rec: dict, known_fields: list) -> dict:
    fields = rec.get("fields", {})
    row = {
        "submit_id": rec["submit_id"],
        "form_id": rec["form_id"],
    }
    # 已知字段单独提取
    for k in known_fields:
        row[k] = fields.get(k)
    # 未知字段放 extra（JSON 字符串，对应数仓 Map 类型）
    extra = {k: v for k, v in fields.items() if k not in known_fields}
    row["extra_fields"] = json.dumps(extra, ensure_ascii=False)
    return row

known = ["name", "phone", "feedback"]   # 业务约定的稳定字段
df = pd.DataFrame([flatten_form(r, known) for r in records])
print(df)
#   submit_id form_id name        phone feedback            extra_fields
# 0      F001   Q2024  张三  13800138000       好                       {}
# 1      F002   Q2024  李四  13900139000      一般  {"satisfaction": 4}
# 2      F003   Q2024  王五  13700137000       差  {"satisfaction": 2, "channel": "APP"}
```

```sql
-- Hive/Spark SQL 落表：extra_fields 用 MAP<STRING,STRING>
CREATE TABLE IF NOT EXISTS ods.ods_form_submission (
    submit_id    STRING,
    form_id      STRING,
    name         STRING,
    phone        STRING,
    feedback     STRING,
    extra_fields MAP<STRING,STRING>
) PARTITIONED BY (dt STRING)
STORED AS ORC;
```

**动态字段落表的两种方案对比**：

| 方案 | 实现 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| Map 列（推荐） | 常用字段成列 + 其余进 `MAP<STRING,STRING>` | Schema 稳定、加字段无需改表 | Map 内字段查询语法稍繁 | 字段长期演化、80% 稳定 |
| 横向扩展列 | 每个新字段 `ALTER TABLE ADD COLUMN` | 查询简单 `SELECT satisfaction` | 频繁改表、列爆炸、历史数据 NULL | 字段基本固定 |

## 五、富文本提取

### 5.1 HTML 正文提取（去标签、保留结构）

网页抓取或富文本编辑器提交的内容是 HTML，需要去标签保留语义结构。直接用正则去标签会丢信息（如 `<p>` 换行、`<li>` 列表），用 BeautifulSoup 更可靠。

```python
from bs4 import BeautifulSoup
import re

html = """
<html>
<head><title>退款申请说明</title><style>.nav{color:red}</style></head>
<body>
<div class="nav">导航栏 | 关于我们 | 联系方式</div>
<div class="content">
  <h1>退款申请</h1>
  <p>订单号：<strong>ORD20240115001</strong></p>
  <p>金额：<strong>299 元</strong></p>
  <p>原因：</p>
  <ul>
    <li>商品质量问题</li>
    <li>物流太慢</li>
  </ul>
  <p>详情见 <a href="https://help.example.com/refund">退款政策</a></p>
</div>
<div class="footer">Copyright 2024</div>
</body>
</html>
"""

soup = BeautifulSoup(html, "html.parser")

# 步骤1：去掉不需要的标签（script/style/nav/footer）
for tag in soup(["script", "style"]):
    tag.decompose()
for selector in [".nav", ".footer"]:
    for tag in soup.select(selector):
        tag.decompose()

# 步骤2：保留正文结构，把块级标签转成换行
content_div = soup.select_one(".content") or soup.body
# get_text 用分隔符保留块级换行
text = content_div.get_text(separator="\n", strip=True)
# 合并多余空行
text = re.sub(r"\n{2,}", "\n", text)
print(text)
```

**HTML 提取要点**：
1. **先删干扰标签**（script/style/nav/footer/广告位）再取正文，否则正文会被噪声污染
2. **用 `separator="\n"` 保留块级换行**，直接 `get_text()` 会把所有内容挤成一行
3. **正文容器定位**：优先用语义选择器（`.content`/`article`/`#main`），兜底用 `body`
4. **链接文本与 URL 分离**：如需保留 URL，单独遍历 `<a>` 标签

### 5.2 提取结构化信息（从正文中抽取关键字段）

正文提取只是第一步，业务分析还需要从自由文本里抽订单号、金额、日期等字段。

```python
import re
import pandas as pd

# 业务字段抽取规则集
FIELD_PATTERNS = {
    "order_id":   re.compile(r"(?:订单号|订单编号|单号)[:：\s]*(?P<val>ORD\d{8,})"),
    "amount":     re.compile(r"(?:金额|退款金额|实付)[:：\s]*(?P<val>\d+(?:\.\d+)?)\s*元"),
    "phone":      re.compile(r"(?:电话|手机|联系方式)[:：\s]*(?P<val>1[3-9]\d{9})"),
    "date":       re.compile(r"(?:日期|时间)[:：\s]*(?P<val>\d{4}[-/]\d{1,2}[-/]\d{1,2})"),
    "email":      re.compile(r"(?:邮箱|Email)[:：\s]*(?P<val>[\w.+-]+@[\w-]+\.[\w.-]+)"),
}

def extract_fields(text: str) -> dict:
    """从自由文本抽取结构化字段"""
    result = {}
    for field, pattern in FIELD_PATTERNS.items():
        m = pattern.search(text)
        if m:
            val = m.group("val")
            # 类型转换
            if field == "amount":
                val = float(val)
            result[field] = val
    return result

# 应用：把邮件正文/聊天内容批量字段化
texts = [
    "订单号：ORD20240115001，金额：299 元，电话：13800138000",
    "退款金额：99.50元，日期：2024-01-15",
    "无具体信息，只是抱怨",
]
df = pd.DataFrame({"raw_text": texts})
fields_df = df["raw_text"].apply(extract_fields).apply(pd.Series)
df_final = pd.concat([df, fields_df], axis=1)
print(df_final)
```

**字段抽取工程化建议**：
1. **规则集集中维护**：所有正则放一个配置文件或类，不要散落各处
2. **优先精确规则，兜底 NER**：能用正则抽的不要上模型（快、可解释）；正则覆盖不到的再上 NLP 命名实体识别

## 六、Schema 设计原则

转换后的目标表怎么设计，直接决定下游好不好用。

### 6.1 字段命名规范

| 规则 | 示例 | 说明 |
|------|------|------|
| 全小写 + 下划线 | `order_id`、`msg_time` | 与 Hive/Spark 习惯一致，避免大小写问题 |
| 业务前缀区分来源 | `chat_*`、`email_*`、`form_*` | 多源合并时一眼看出字段来源 |
| 时间字段统一后缀 | `create_time`、`submit_time`、`msg_time` | 区分各环节时间点 |
| 布尔字段用 is/has 前缀 | `is_refunded`、`has_attachment` | 语义清晰 |
| 原始内容保留 raw 列 | `raw_text`、`raw_json` | 方便回溯和重解析 |

### 6.2 类型选择

| 数据 | 推荐类型 | 避免 |
|------|---------|------|
| 订单号/手机号 | STRING | 不要用 BIGINT（前导零会丢、超 long 会溢出） |
| 金额 | DECIMAL(12,2) | 不要用 FLOAT/DOUBLE（精度问题） |
| 时间戳 | TIMESTAMP | 不要用 STRING 存（无法直接做时间函数） |
| 消息类型/状态 | STRING + 枚举注释 | 不要用 INT 编码（可读性差） |
| 标签数组 | ARRAY<STRING> | 不要用逗号拼接 STRING（无法 explode） |
| 动态扩展字段 | MAP<STRING,STRING> | 不要每来一个字段就 ALTER TABLE |

### 6.3 空值处理

```python
import pandas as pd
import numpy as np

# 转换时统一空值表示，避免下游歧义
# 源端空值花样：空字符串、NULL、null、NaN、None、"无"、"未填写"
NULL_TOKENS = {"", "null", "NULL", "None", "nan", "NaN", "无", "未填写", "N/A", "n/a"}

def normalize_null(val):
    """统一空值为 None（对应数仓 NULL）"""
    if val is None or (isinstance(val, float) and np.isnan(val)):
        return None
    if isinstance(val, str) and val.strip() in NULL_TOKENS:
        return None
    return val

df = df.applymap(normalize_null)
```

**原则**：源端各种"空"的表达统一转成 `NULL`，不要让空字符串、`"无"`、`"未知"` 混进数仓，否则 `WHERE col IS NULL` 永远查不全。

### 6.4 动态字段落表

详见 4.4 节，核心结论：

```
动态字段落表决策:

字段是否长期稳定?
├── 是 → 单独成列（ALTER TABLE ADD COLUMN，低频）
└── 否 → 进 MAP<STRING,STRING> 列
         └── 常用查询字段再建视图单独提取

示例：
  原始表 ods_form_submission: name, phone, feedback, extra_fields MAP
  视图 dwd_form_submission_v: name, phone, feedback,
         extra_fields['satisfaction'] AS satisfaction,
         extra_fields['channel'] AS channel
```

## 八、小结

| 源类型 | 解析工具 | 关键函数/方法 | 输出 Schema 示例 |
|--------|---------|--------------|-----------------|
| 嵌套 JSON | Spark `from_json`+`explode` | `from_json`、`explode`、`get_json_object` | `feedback_id, user_id, msg_seq, msg_type, msg_content` |
| 嵌套 JSON（小数据） | pandas `json_normalize` | `record_path`、`meta` | 同上 |
| XML | lxml / ElementTree | `xpath`、`findtext`、`get` | `order_id, customer_name, sku_id, qty, price` |
| CSV/TSV | pandas `read_csv` | `dtype=str`、`sep`、`encoding` | 原样字段，统一字符串读入 |
| 聊天记录（微信/企微/钉钉） | 正则 + 状态机 | `TIME_LINE`、`detect_msg_type` | `msg_time, sender, dept, msg_type, content, raw` |
| 邮件 `.eml` | 标准库 `email` | `message_from_binary_file`、`decode_header` | `from, to, subject, date, body, attachments` |
| 动态表单 | pandas + JSON | `flatten_form`、Map 列 | `submit_id, name, phone, extra_fields(MAP)` |
| HTML 富文本 | BeautifulSoup | `decompose`、`get_text(separator)` | `title, content, links` |
| 自由文本字段抽取 | 正则规则集 | 命名捕获组 `(?P<val>)` | `order_id, amount, phone, date` |

**核心工程原则**：
1. **保留 raw 列**：正则/解析器永远有漏网之鱼，留原始内容方便回溯和重解析
2. **解析失败要可见**：未匹配行带行号落表，监控失败率，平台格式变更会突然拉高失败率
3. **确定性优先**：能用正则/规则精确提取的，不要上 NLP 模型（快、可解释、好维护）
4. **动态字段用 Map**：Schema 演化的字段进 `MAP<STRING,STRING>`，不要频繁 ALTER TABLE
5. **类型选对**：订单号/手机号用 STRING 不用 BIGINT，金额用 DECIMAL 不用 DOUBLE
6. **空值统一**：源端各种"空"（空串/NULL/无/未填写）统一转成 NULL
