## 二、问题场景（你的真实痛点）

### 2.1 场景复现

假设你在做一个用户反馈分析平台，数据来自三个渠道：

```
渠道A：APP 内置反馈表单
  - 字段：user_id（APP注册ID）、phone、feedback_text、submit_time
  - 示例：user_id=U10023, phone=13800138000, feedback="支付失败"

渠道B：客服聊天记录
  - 字段：session_id、customer_phone（可能为空）、openid（微信）、chat_text、chat_time
  - 示例：session_id=S5891, openid=oXxx_abc, chat_text="我昨天付款一直转圈"

渠道C：邮件工单
  - 字段：ticket_id、email、subject、body、create_time
  - 示例：ticket_id=T20250715, email=zhangsan@qq.com, subject="退款问题"
```

**问题1：同一个用户在三个渠道用了三个不同身份**
- 渠道A：U10023 / 13800138000
- 渠道B：openid=oXxx_abc（同一个手机号 13800138000，但渠道B 没填手机号）
- 渠道C：zhangsan@qq.com（同一个人，但渠道A/B 没有 email）

**如果不做 ID Mapping**：你会把同一个人的反馈算成三个不同用户的反馈，NPS（净推荐值）统计完全失真。

**问题2：同一个地区名/职业名/商品名有不同写法**
- 地区："北京" / "北京市" / "BJ" / "Beijing" / "beijing"
- 职业："前端工程师" / "前端开发" / "FE" / "Front-end Engineer"
- 商品："iPhone 15 Pro 256G" / "苹果15Pro 256G" / "iPhone15 Pro 256GB"

**如果不做标准化**：按地区 group by 会得到 5 行北京，按商品 group by 会得到 3 行 iPhone，统计结果不可用。

### 2.2 问题本质

| 问题类型 | 本质 | 解决思路 |
|---------|------|---------|
| ID Mapping | 同一实体（人）在不同源有不同标识符 | 通过共享属性建立关联，用图算法找联通分量 |
| 枚举标准化 | 同一概念（值）有不同字符串表达 | 字典映射 + 模糊匹配归一 |

## 三、ID Mapping：跨渠道用户身份打通

### 3.1 问题形式化

**输入**：多渠道用户记录，每条记录可能携带一个或多个标识符

```
记录1: {channel: APP,    user_id: U10023, phone: 13800138000,                 }
记录2: {channel: APP,    user_id: U10023,                  email: a@x.com     }
记录3: {channel: Chat,   session: S5891,  phone: 13800138000, openid: oXxx_abc}
记录4: {channel: Email,  ticket: T2025,                    email: a@x.com     }
记录5: {channel: Chat,   session: S5892,  openid: oXxx_abc                   }
```

**目标**：识别出记录1/2/3/4/5 都属于同一个真实用户，分配统一的 `global_user_id`。

### 3.2 方法1：确定性规则匹配（基础）

**思路**：如果两条记录有相同的 phone 或相同的 email 或相同的 openid，则认为是同一用户。

**问题**：链式传递。记录1 和记录3 共享 phone，记录3 和记录5 共享 openid，记录1 和记录2 共享 user_id，记录2 和记录4 共享 email。所以 1-2-3-4-5 全部属于同一用户。简单的 JOIN 只能两两匹配，无法处理这种传递性。

### 3.3 方法2：图算法——联通分量（推荐）

**思路**：把每条记录的每个标识符看作图中的节点，同一条记录内的标识符之间连边。然后用联通分量算法（Connected Components）找出所有联通的节点集合，每个集合就是一个真实用户。

```
图结构：
  U10023 ─── 13800138000 ─── oXxx_abc
    │
    └────── a@x.com

联通分量：{U10023, 13800138000, oXxx_abc, a@x.com} → global_user_id = G00001
```

#### 3.3.1 Python 实现（Union-Find 算法，适合中小规模）

```python
"""
id_mapping_unionfind.py
用 Union-Find（并查集）实现 ID Mapping
适合：标识符总量 < 1000万（单机可处理）
"""
from collections import defaultdict


class UnionFind:
    """并查集，支持路径压缩和按秩合并"""

    def __init__(self):
        self.parent = {}
        self.rank = {}

    def find(self, x):
        if x not in self.parent:
            self.parent[x] = x
            self.rank[x] = 0
            return x
        # 路径压缩
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return
        # 按秩合并
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1


def build_id_mapping(records):
    """
    输入：records，每条是 dict，包含多个标识符字段
    输出：{标识符: global_user_id} 的映射表

    records = [
        {"user_id": "U10023", "phone": "13800138000"},
        {"user_id": "U10023", "email": "a@x.com"},
        {"phone": "13800138000", "openid": "oXxx_abc"},
        {"email": "a@x.com"},
    ]
    """
    uf = UnionFind()

    # 标识字段名（根据业务定义）
    id_fields = ["user_id", "phone", "email", "openid", "device_id", "unionid"]

    for record in records:
        # 提取这条记录里所有非空的标识符
        ids_in_record = []
        for field in id_fields:
            val = record.get(field)
            if val:
                # 加前缀防止跨字段冲突（phone 的 "13800" 和 user_id 的 "13800" 不会误连）
                ids_in_record.append(f"{field}:{val}")

        # 同一条记录内的所有标识符两两连边
        for i in range(1, len(ids_in_record)):
            uf.union(ids_in_record[0], ids_in_record[i])

    # 分配 global_user_id
    component_map = defaultdict(list)
    for node in uf.parent:
        root = uf.find(node)
        component_map[root].append(node)

    # 生成映射表
    id_to_global = {}
    for idx, (_, nodes) in enumerate(component_map.items(), start=1):
        gid = f"G{idx:06d}"
        for node in nodes:
            id_to_global[node] = gid

    return id_to_global


# ========== 测试 ==========
if __name__ == "__main__":
    records = [
        {"user_id": "U10023", "phone": "13800138000"},
        {"user_id": "U10023", "email": "a@x.com"},
        {"phone": "13800138000", "openid": "oXxx_abc"},
        {"email": "a@x.com"},
        {"openid": "oXxx_abc", "device_id": "DEV_8899"},
        {"user_id": "U99999", "phone": "13900139000"},  # 另一个用户
    ]

    mapping = build_id_mapping(records)
    for k, v in mapping.items():
        print(f"{k} -> {v}")

    # 预期：U10023/13800138000/a@x.com/oXxx_abc/DEV_8899 应该是同一个 G000001
    # U99999/13900139000 应该是另一个 G000002
```

#### 3.3.2 Spark GraphFrame 实现（适合亿级规模）

```python
"""
id_mapping_spark.py
用 Spark GraphFrame 的联通分量算法实现 ID Mapping
适合：标识符总量 > 1000万，需要分布式计算
依赖：spark-graphframes 包
"""
from pyspark.sql import SparkSession, functions as F, types as T
from graphframes import GraphFrame

spark = SparkSession.builder \
    .appName("IDMapping") \
    .config("spark.jars.packages", "graphframes:graphframes:0.8.2-spark3.0-s_2.12") \
    .getOrCreate()

# ========== 1. 加载多渠道用户记录 ==========
# 假设已经采集到一张宽表 raw_user_ids
raw_df = spark.read.parquet("/warehouse/ods/raw_user_ids")
# schema: channel, record_id, user_id, phone, email, openid, device_id, unionid

# ========== 2. 展开为（record_id, id_type, id_value）长表 ==========
id_fields = ["user_id", "phone", "email", "openid", "device_id", "unionid"]

id_long_df = raw_df.selectExpr("record_id", *[
    f"struct('{f}' as id_type, {f} as id_value) as {f}_struct"
    for f in id_fields
]).selectExpr("record_id", *[
    f"{f}_struct" for f in id_fields
])

# 用 explode 展开成行
from pyspark.sql import functions as F

rows = []
for f in id_fields:
    rows.append(
        raw_df.filter(F.col(f).isNotNull())
        .select(F.lit(f).alias("id_type"), F.col(f).alias("id_value"), F.col("record_id"))
    )
id_long_df = rows[0]
for r in rows[1:]:
    id_long_df = id_long_df.union(r)

# 生成全局唯一节点 id（加类型前缀防冲突）
id_long_df = id_long_df.withColumn(
    "node_id",
    F.concat(F.col("id_type"), F.lit(":"), F.col("id_value"))
)

# ========== 3. 构建图 ==========
# 节点：所有出现过的标识符
vertices = id_long_df.select(
    F.col("node_id").alias("id")
).distinct()

# 边：同一条 record 内的标识符两两连边
# 先按 record_id 分组收集所有 node_id，再 explode 两两组合
edges = id_long_df.groupBy("record_id").agg(
    F.collect_set("node_id").alias("nodes")
).withColumn("node_a", F.explode("nodes")) \
 .withColumn("node_b", F.explode("nodes")) \
 .filter(F.col("node_a") < F.col("node_b")) \
 .select(
     F.col("node_a").alias("src"),
     F.col("node_b").alias("dst")
 ).distinct()

g = GraphFrame(vertices, edges)

# ========== 4. 联通分量 ==========
# spark.graphframes 的 connectedComponents 默认用哈希切分，适合大图
cc = g.connectedComponents(
    algorithm="graphx",       # graphx 比 labelPropagation 快且精确
    checkpointInterval=10,
    broadcastThreshold=1000000
)

# cc schema: id, component
# component 是一个 Long 型 ID，同一个联通分量的节点 component 相同

# ========== 5. 分配 global_user_id 并写回 ==========
# 每个 component 选一个稳定的代表 ID 作为 global_user_id
global_id_map = cc.groupBy("component").agg(
    F.min("id").alias("global_user_id")  # 取字典序最小的作为代表
).join(cc, "component", "inner") \
 .select("id", "global_user_id")

global_id_map.write.mode("overwrite").saveAsTable("dwd.user_id_mapping")

# ========== 6. 验证 ==========
# 抽样检查：同一个 global_user_id 下有多少种渠道、多少个标识符
verify = spark.sql("""
    SELECT
        m.global_user_id,
        COUNT(DISTINCT r.channel) AS channel_cnt,
        COUNT(DISTINCT m.id) AS id_cnt,
        COLLECT_LIST(m.id) AS all_ids
    FROM dwd.user_id_mapping m
    JOIN ods.raw_user_ids r
      ON m.id = CONCAT('user_id:', r.user_id)
      OR m.id = CONCAT('phone:', r.phone)
      OR m.id = CONCAT('email:', r.email)
    GROUP BY m.global_user_id
    HAVING channel_cnt >= 2
    LIMIT 10
""")
verify.show(truncate=False)
```

### 3.4 方法3：概率性匹配（进阶，可选）

**何时用**：当确定性匹配（共享 phone/email）覆盖率不足，需要用行为特征辅助判断两个 ID 是否是同一人。

**思路**：用 Logistic Regression 模型，特征包括：
- 两个 ID 的登录 IP 重合度
- 两个 ID 的活跃时段重合度
- 两个 ID 的设备指纹相似度
- 两个 ID 的购买品类重合度

输出：两个 ID 属于同一人的概率 P，设阈值（如 0.85）判定为同一人。

```python

概率性 ID Mapping 示例（伪代码框架）
注意：需要先有正样本（已知同一人的 ID 对）来训练
"""

from sklearn.model_selection import train_test_split
import numpy as np

# 候选对生成：用 LSH（Locality Sensitive Hashing）从海量 ID 对中筛出可能匹配的，避免 O(n²)
def extract_features(id_pair, behavior_table):
    id_a, id_b = id_pair
    # 特征1：IP 重合度
    ip_jaccard = jaccard(
        behavior_table[id_a]["ips"],
        behavior_table[id_b]["ips"]
    )
    # 特征2：活跃时段重合度
    hour_overlap = time_overlap(
        behavior_table[id_a]["active_hours"],
        behavior_table[id_b]["active_hours"]
    )
    # 特征3：设备指纹相似度
    device_sim = device_similarity(
        behavior_table[id_a]["device_fp"],
        behavior_table[id_b]["device_fp"]
    )
    return [ip_jaccard, hour_overlap, device_sim]

# 训练
# X: 特征矩阵, y: 0/1 标签（1=同一人）
# 正样本来源：手机号验证过的 ID 对、用户手动关联的账号
# 负样本来源：随机抽样明显不同的 ID 对
model = LogisticRegression(class_weight="balanced")
model.fit(X_train, y_train)
```

> **工程提示**：概率性匹配的误判率不可忽视。生产环境建议先跑确定性匹配（覆盖 70-80%），再用概率性匹配补漏（覆盖额外 10-15%），最后人工审核边界 case。

### 3.5 ID Mapping 的工程化难点

| 难点 | 解决方案 |
|------|---------|
| 增量更新：新数据来了，已存在的 global_user_id 要稳定 | 用增量联通分量算法，或每天全量重算 + 用历史映射表对齐 |
| 错误关联：两个不同人共用了同一个手机号（如客服电话） | 引入"强标识符"（实名认证手机号）和"弱标识符"（设备ID）区分，弱标识符不单独用于合并 |
| 隐私合规：手机号/邮箱是 PII | 映射表单独存储，做脱敏处理，访问审计 |
| 评估质量：没有 ground truth | 用 A/B 抽样人工标注，计算 Precision/Recall |

## 四、枚举值标准化

### 4.1 问题分类

| 类型 | 示例 | 特点 |
|------|------|------|
| 同义词 | "北京"/"北京市"/"BJ"/"Beijing" | 指向同一概念，写法不同 |
| 缩写 | "前端工程师"/"FE"/"Front-end" | 完整 vs 缩写 |
| 格式不统一 | "iPhone 15 Pro 256G"/"iPhone15 Pro 256GB" | 大小写/空格/单位 |
| 拼写错误 | "iPhone 15 Ppr"/"iPone 15 Pro" | 人为输入错误 |

### 4.2 方法1：标准字典映射（精确匹配，首选）

**适用**：枚举值有限（< 几千种），且变化频率低。

```python
"""
枚举标准化：字典映射
适合：地区、性别、职业、行业等有限枚举字段
"""
import pandas as pd

# ========== 1. 维护标准字典 ==========
# 字典应该有版本管理，新增值要审批
region_dict = {
    # 标准值 -> 所有可能的输入写法
    "Beijing":  ["北京", "北京市", "BJ", "beijing", "北京 市", "京"],
    "Shanghai": ["上海", "上海市", "SH", "shanghai", "沪"],
    "Guangzhou": ["广州", "广州市", "GZ", "guangzhou", "穗"],
    "Shenzhen": ["深圳", "深圳市", "SZ", "shenzhen", "深"],
    # ... 完整字典
}

# 反转字典：输入写法 -> 标准值
def build_reverse_dict(std_dict):
    reverse = {}
    for std_val, aliases in std_dict.items():
        for alias in aliases:
            reverse[alias.lower().strip()] = std_val
        reverse[std_val.lower().strip()] = std_val  # 标准值本身
    return reverse

reverse_dict = build_reverse_dict(region_dict)

# ========== 2. 标准化函数 ==========
def standardize_region(raw_value):
    if pd.isna(raw_value):
        return None
    key = str(raw_value).lower().strip()
    return reverse_dict.get(key, None)  # 匹配不到返回 None，进入人工审核队列

# ========== 3. 批量应用 ==========
df = pd.read_csv("user_feedback.csv")
df["region_std"] = df["region_raw"].apply(standardize_region)

# ========== 4. 未匹配的值进入审核队列 ==========
unmatched = df[df["region_std"].isna()]["region_raw"].value_counts()
print("以下值未匹配，需要补充字典：")
print(unmatched)

# 写入待审核表，人工补充字典后重新跑
unmatched.to_csv("dict_review_queue.csv")
```

### 4.3 方法2：模糊匹配（处理未知写法）

**适用**：字典覆盖不全，新出现的写法需要自动归一。

```python
"""
模糊匹配标准化
依赖：pip install rapidfuzz
rapidfuzz 比 fuzzywuzzy 快 10-100 倍，且 license 友好（MIT）
"""
from rapidfuzz import process, fuzz
import pandas as pd

# 标准值列表
standard_regions = ["Beijing", "Shanghai", "Guangzhou", "Shenzhen", "Hangzhou", "Chengdu"]

# 已知别名（作为补充候选）
all_aliases = {
    "Beijing": ["北京", "北京市", "BJ"],
    "Shanghai": ["上海", "上海市", "SH"],
    # ...
}
# 展开成 (alias, standard) 对照表
alias_to_std = {alias: std for std, aliases in all_aliases.items() for alias in aliases}
all_candidates = list(alias_to_std.keys()) + standard_regions

def fuzzy_standardize(raw_value, threshold=85):
    """
    用 rapidfuzz 做模糊匹配
    threshold: 匹配分数阈值，低于此值返回 None（进入人工审核）
    """
    if pd.isna(raw_value):
        return None

    raw = str(raw_value).strip()

    # 第一步：精确匹配（最快）
    if raw in alias_to_std:
        return alias_to_std[raw]
    if raw in standard_regions:
        return raw

    # 第二步：模糊匹配
    # extractOne 返回 (匹配值, 分数, 索引)
    match, score, _ = process.extractOne(
        raw,
        all_candidates,
        scorer=fuzz.WRatio  # WRatio 综合了多种算法，对中英文混合友好
    )

    if score >= threshold:
        # 通过别名找到标准值
        if match in alias_to_std:
            return alias_to_std[match]
        return match
    else:
        return None  # 进入人工审核队列

# ========== 批量应用 ==========
df = pd.read_csv("user_feedback.csv")
df["region_std"] = df["region_raw"].apply(fuzzy_standardize, threshold=85)

# 统计匹配率
total = len(df)
matched = df["region_std"].notna().sum()
print(f"匹配率: {matched}/{total} = {matched/total:.1%}")

# 查看未匹配的
unmatched = df[df["region_std"].isna()]["region_raw"].value_counts().head(20)
print("未匹配 Top20：")
print(unmatched)
```

#### 4.3.1 模糊匹配算法选择指南

| 算法 | 适用场景 | rapidfuzz 函数 |
|------|---------|---------------|
| WRatio | 通用，中英文混合 | `fuzz.WRatio` |
| ratio | 整体相似度（编辑距离变体） | `fuzz.ratio` |
| partial_ratio | 子串匹配（"北京" in "北京市朝阳区"） | `fuzz.partial_ratio` |
| token_sort_ratio | 词序无关（"前端 工程师" vs "工程师 前端"） | `fuzz.token_sort_ratio` |
| token_set_ratio | 词序无关 + 去重 | `fuzz.token_set_ratio` |

```python
# 不同算法对比示例
from rapidfuzz import fuzz

print(fuzz.WRatio("北京", "北京市"))           # 95
```

### 4.4 方法3：规则 + ML 混合（处理大规模商品名）

**适用**：商品名、公司名等长文本，且枚举值上万种。

**思路**：
1. 用规则提取关键特征（品牌、型号、规格）
2. 用分类器或聚类把相似商品归到同一 SKU

```python
"""
商品名标准化：规则 + ML
适合：电商场景，商品名自由文本，需要归一到标准 SKU
"""
import re
import pandas as pd
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.cluster import DBSCAN

# ========== 1. 规则提取特征 ==========
def extract_product_features(name):
    """从商品名提取结构化特征"""
    name = str(name).upper().strip()

    # 提取品牌
    brands = ["IPHONE", "HUAWEI", "XIAOMI", "SAMSUNG", "OPPO", "VIVO"]
    brand = next((b for b in brands if b in name), "UNKNOWN")

    # 提取型号（如 iPhone 15）
    model_match = re.search(r'(?:IPHONE|IPHONE)\s*(\d+)', name)
    model = model_match.group(1) if model_match else "UNKNOWN"

    # 提取版本（Pro/Max/Plus）
    edition = "STANDARD"
    for e in ["PRO MAX", "PRO", "MAX", "PLUS", "MINI", "SE"]:
        if e in name:
            edition = e.replace(" ", "_")
            break

    # 提取存储容量
    storage_match = re.search(r'(\d+)\s*(?:G|GB|T|TB)', name)
    storage = storage_match.group(1) + "G" if storage_match else "UNKNOWN"

    return f"{brand}_{model}_{edition}_{storage}"

# ========== 2. 规则归一 ==========
df = pd.read_csv("products.csv")
df["sku_key"] = df["product_name"].apply(extract_product_features)

# 此时 "iPhone 15 Pro 256G" / "苹果15Pro 256G" / "iPhone15 Pro 256GB"
# 都会被归到 IPHONE_15_PRO_256G

# ========== 3. 对规则未覆盖的，用 TF-IDF + DBSCAN 聚类 ==========
unmatched = df[df["sku_key"].str.contains("UNKNOWN")]
if len(unmatched) > 0:
    tfidf = TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4))
    X = tfidf.fit_transform(unmatched["product_name"])

    # DBSCAN 聚类：相似度高的归为一类
    clustering = DBSCAN(eps=0.3, min_samples=2, metric="cosine").fit(X)
    unmatched["cluster"] = clustering.labels_

    # 每个 cluster 选一个代表名作为标准 SKU
    # -1 是噪声点，单独处理
```

### 4.5 字典维护流程（工程化关键）

标准化字典不是一次性的，需要持续维护：

```
字典维护流程：

1. 发现新值
   └─ 清洗时遇到未匹配的值 → 进入 review_queue 表

2. 人工审核（每周）
   └─ 数据治理员审核 review_queue
   ├─ 能映射到现有标准值 → 补充别名
   └─ 是新枚举值 → 新增标准值 + 审批

3. 字典版本化
   └─ 每次变更生成新版本（v1.0 → v1.1）
   └─ 历史版本保留，支持回溯重算

4. 影响评估
   └─ 字典变更后，下游报表需要重算吗？
   └─ 用版本号标记每条数据是用哪个版本字典标准化的

5. 回溯重算
   └─ 字典 v1.1 上线后，重算近 30 天数据
   └─ 对比 v1.0 和 v1.1 结果差异，通知下游
```

## 六、小结

| 问题 | 推荐方法 | 工具 |
|------|---------|------|
| 跨渠道用户身份打通（小规模） | Union-Find 联通分量 | Python 自实现 |
| 跨渠道用户身份打通（大规模） | GraphFrame 联通分量 | Spark GraphFrame |
| 跨渠道身份补漏（无共享标识符） | 概率性匹配（LR 模型） | sklearn + 行为特征 |
| 有限枚举值标准化 | 字典精确匹配 | Python dict |
| 枚举值含拼写错误/写法差异 | 字典 + rapidfuzz 模糊匹配 | rapidfuzz |
| 长文本实体（商品名/公司名）归一 | 规则提取 + TF-IDF 聚类 | sklearn |

**核心工程原则**：
1. **确定性优先**：能用规则/字典精确匹配的，不要用模糊算法（避免误判）
2. **人工兜底**：模糊匹配设阈值，低于阈值的进人工审核队列，不要强行归一
3. **版本化**：字典和映射表都要版本化，支持回溯
4. **评估闭环**：定期抽样人工标注，计算 Precision/Recall，监控质量退化
